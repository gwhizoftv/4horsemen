### Findings

1. **Cursor — `src/setupWorkspace.ts:308` (P2): preserve a working Make verification policy when adding Python inference.** A Python marker must not replace an already inferred `make check`/`make test` workflow merely because onboarding is run again. With a root pyproject and a Makefile whose test target runs `python -m unittest discover` or prepares an environment before tests, Cursor returns the Python proposal before inspecting Make. Re-onboarding replaces those commands with bare `pytest -q`, drops the existing check target, and can fail doctor on a previously supported product with no pytest executable or run tests without required setup. The targeted source probe confirmed this replacement; Claude and Codex retained Make. A regression should combine a Python marker with both `check` and `test` Make targets and assert the existing Make commands survive, while an auxiliary-only Makefile still falls through to Python. This is the compatibility correction raised during plan review; the original plan's unconditional Python-before-Make order did not distinguish usable gates from auxiliary targets.

2. **Claude — `src/setupWorkspace.ts:244`; Cursor — `src/setupWorkspace.ts:286` (P2): limit Flutter fallback to products without an existing usable verification gate.** Additional language support should preserve an already working Node finalization script or Make test target on reinstallation. Both implementations return Flutter before examining either detector. A Flutter product with a Make test target that generates required code or a Node check script that covers backend and mobile components loses that setup or additional coverage: its recorded finalization becomes only `flutter analyze` and `flutter test`. The source probes confirmed replacement for both working Make and working Node fixtures. Although Flutter-before-Node follows the original plan's order, the stated reason was an incidental tooling manifest; a working finalization script is a different case. Add cases with a Flutter pubspec plus a Node `check` script, and plus a Make `test` target, asserting the original gates remain; retain the positive case where an incidental package manifest has no finalization script. Codex passes these source probes. Claude's Make preservation currently applies to Python only.

3. **Cursor — `src/setupWorkspace.ts:383` (P2): render the effective documentation policy rather than assume its checks are empty.** Declared documentation profiles may contain nonempty local and final checks, and the new onboarding announcement must describe what was recorded. This line always prints `empty checks`, including when `config.documentation.verify.precommit` contains a docs linter and `config.documentation.checks` contains a docs test. The targeted renderer probe produced `1 path(s), empty checks (declared)` for that nonempty profile, telling the owner that documentation changes are exempt when they will execute checks. A regression should provide a declared documentation profile with nonempty commands and assert the announcement includes those commands and does not claim an empty gate. Codex renders all three documentation phases; Claude lists documentation paths without making Cursor's false empty-check claim.
