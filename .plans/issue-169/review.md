## Findings

1. **cursor — Exact File List / Reuse (`clearReady` with `clearCompletion`, including accept).** The plan says to clear `ready` “wherever `clearCompletion` already runs for drop/retire/accept transitions.” Rule: the issue deletes `ready` only once the next action’s nudge is sent; acceptance of the prior `complete` must leave the receipt in place for that next send. Smallest correction: clear `ready` only after a successful nudge (and on drop/retire/owner wipe), never on accept or action preparation — as codex and claude already specify.

2. **cursor — Exact File List omits `src/tmux.ts`.** The plan claims runLoop can accept a ready-file proof “that does not require `requireIdleSentinel`” while listing only `runLoop.ts` for delivery. Failure if followed: Claude/Cursor panes that show a vendor prompt without the sentinel at the capture tail still return `no-idle-sentinel` even when runLoop chose a ready-file override, so issue 169 stays broken for the agents that cannot pass `sentinelAtTail`. Smallest correction: add `src/tmux.ts` and thread an explicit proof source through `staleOverride` (claude/codex shape).

3. **cursor — Exact File List / “pass `readyPath`” without `src/steps.ts`.** The plan has runLoop pass `readyPath` into orders. Rule: `InternalOrder` is defined in `src/steps.ts` and today only has `completePath`; adding a field is a steps change, and a path cited only in prose is not an approved edit. Prefer codex’s map; fold in claude’s Claude/Cursor footer diagnosis for test fixtures; reject cursor’s accept-time cleanup and missing tmux edit.
