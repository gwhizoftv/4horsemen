They differ in guard binding, probe safety, and watchdog scope.

## Comparison

1. **Guard binding scope (muse `src/hookPolicy.ts:194`).** The rule that must hold: every outgoing update of the agent's own issue branch in one push must be checked, because Git delivers all ref lines to the pre-push hook at once. Concrete failure: the muse guard derives the branch from the first issue-shaped update and skips later refs (`remoteBranch !== branch` continues), and returns `null` for the whole push when that first branch belongs to a peer — so `git push origin issue-256/claude issue-256/muse` (or a peer ref listed first) publishes an unchecked artifact while the hook reports success. Claude (`checkRequiredArtifact`) and codex (`assertRequiredArtifact`) both iterate per-ref. Smallest illustrative test: in `test/hookSync.test.ts`, push two refs in one command with the artifact missing from the second and expect a block naming the path.

2. **Guard inspection precision (muse `src/hookPolicy.ts:194`; claude `src/hookPolicy.ts:216`).** The rule that must hold: the pushed artifact must be a regular blob at the exact literal path, with staged, unmerged, and worktree states distinguished, using the repository's normal filter semantics. Concrete failure: both muse and claude hash the worktree with plain `git hash-object -- <path>`, which ignores `.gitattributes` filters for that path, so an artifact under a `text`/`eol` attribute can hash differently from its committed blob and block a clean push (or, conversely, mask a real difference); neither checks the blob mode, and muse does not use `--literal-pathspecs`, so a glob character in a required path matches other paths. Codex checks mode/`--path=`/literal pathspecs but adds its own defect in Finding 3. Smallest fix: adopt codex's `hash-object --path=<path>` plus literal pathspecs and a `100644|100755 blob` tree check in the muse/claude shape.

3. **Non-HEAD pushes (codex `src/hookPolicy.ts`, `assertRequiredArtifact`).** The rule that must hold: the guard validates the outgoing commit named on the ref line, not local `HEAD`. Concrete failure: codex additionally requires `ls-tree HEAD -- <path>` to equal the pushed tree, so pushing an older commit (`git push origin HEAD~1:issue-256/codex`) after the artifact has been edited and committed locally is blocked even though the pushed tree is complete and clean — a legitimate publication the selected plan's “checks a non-HEAD outgoing SHA correctly” was meant to allow. Claude and muse compare only against the outgoing SHA. Smallest fix: delete the `HEAD` equality clause; the index-versus-pushed-tree comparison already catches staged divergence.

4. **Watchdog probe cost and completeness (codex `src/runLoop.ts`, `cloneActivityStamp`; claude `src/runLoop.ts`, `cloneActivityStamp`).** The rule that must hold: clone observation must be bounded and must not become permanently unavailable on large-but-healthy repositories, or stall detection silently dies. Concrete failure: codex enumerates `--cached --others` (every tracked file) and treats more than 4,096 files as an incomplete observation, so on any clone with more than 4,096 tracked files the stamp is `null` on every tick and a genuinely stalled agent is never resent and never reported; claude's 2,000-path cap over modified/untracked files has the same failure mode for a very dirty clone, while muse enumerates only `--modified --others` and so stays proportional to actual changes. Smallest illustrative test: a fixture clone with the cap exceeded plus a static pane must still reach `[WAIT]` (deferral must be bounded, e.g. fall back to index-only metadata past the cap).

5. **Watchdog probe execution (muse `src/runLoop.ts:2059`).** The rule that must hold: a once-a-minute probe inside the coordinator loop must be asynchronous and time-bounded, like the existing `processRunner` observations. Concrete failure: muse runs synchronous `git` (via `src/gitExec.ts`) and synchronous `statSync` inside `watchOwedWork` on the tick path, so a slow filesystem or a clone where `git ls-files` hangs stalls the whole coordinator loop for every agent, not just the one owed; claude and codex both await `this.processRunner` with a timeout and treat 32 KiB-truncated output as unavailable. Smallest fix: move the muse stamp behind `processRunner` with the same timeout/truncation handling, keeping its `--modified --others` enumeration.

6. **Busy-indicator scope (muse `src/tmux.ts:281-298`).** The rule that must hold: busy evidence is live vendor chrome near the pane tail; quoted history must not suppress stall recovery. Concrete failure: for claude/cursor/antigravity the muse predicate accepts `esc to cancel` anywhere in the unfenced pane, so a transcript that quotes an old “esc to cancel” line keeps the agent “busy” until it scrolls off, delaying the one resend; codex restricts the search to the region above the composer, the last eight lines, and excludes quoted/bulleted lines, and claude restricts to the last eight non-empty lines. Smallest fix: adopt the tail/above-composer restriction. Separately, codex is the only pin that bounds the frozen-chrome failure (busy delays resend by at most five quiet minutes before `[WAIT]`), which the muse and claude pins leave unbounded.

7. **Selected-plan fidelity: terminal logs (codex `src/runLoop.ts`, `watchOwedWork`).** The rule that must hold: an implementation follows the selected plan or explicitly re-decides it; the selected plan required observing `run-*.log` files under `agentRuntimePaths(...).terminalLogs`. Concrete failure: codex omits terminal-log observation entirely (with a code comment arguing pane logs include owner drafts and footer repaint), so a hookless agent whose only observable activity is terminal output growth — static clone, static pane digest region, no transcript — is still falsely resent; muse and claude both implement the log stamp as planned. This is a justified-looking deviation, but it is a deviation: it should be accepted explicitly by reviewers rather than discovered. Smallest illustrative test: append to a `run-*.log` each minute with everything else static and expect no resend.

8. **Tests and scope discipline (all pins).** Each pin stays within the issue, reuses existing fixtures (`safetyFixture`, `installed`/`activeRun`, `order()`), and adds only focused coverage to the four approved test files; no pin adds dependencies, config, or unrelated refactors. The material differences are depth, not discipline: claude and codex cover staged/untracked/unmerged/wrong-SHA and busy-then-idle transitions more completely, while the muse pin's coverage is the thinnest (one guard case, one clone-edit case, one busy case) and would not catch Findings 1, 2, or 5. Verification note: this comparison read the bound worktrees and existing verification results only; no product suite was run for this evidence-only action, and missing results are not treated as a pass.

Recommendation: prefer the claude pin `f768700b2183852d0606e0877675314ff04c1acc` as the base — its per-ref, owed-status, literal-pathspec guard and its asynchronous, truncation-aware probe are the soundest combination — after fixing Finding 2 (`--path=` hashing) and Finding 4 (bounded fallback past the path cap). The codex pin `4a41284dacb1380fa4687ef0ed7479b38f85a815` is a close second if Findings 3, 4, and 7 are corrected. The muse pin `4d1f81306a72f6629cfc05fdb86d5c969ec7a18e` should not be selected without fixing Findings 1, 5, and 6.
