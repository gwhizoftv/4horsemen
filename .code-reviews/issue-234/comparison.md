**Findings requiring revision**

1. **[P2] Codex — `scripts/setup_common.sh:307`.** Every shell bridge that loads coordinator JavaScript must select the coordinator runtime independently of the product's Node; the selected plan explicitly includes `common_configure_trust`. This bridge still executes bare `node`. Consequently, a configured compatible `COORD_NODE` is ignored while legacy setup loads the coordinator trust module under the product's old runtime. In an isolated execution of this exact function, a product Node stub reporting `v16.18.0` and refusing JavaScript caused exit 71 before trust configuration, despite a working Node 26 override. The other three implementations reached the same fixture trust module. Extend the existing setup-trust test with an old ambient Node and a supported override, and route this bridge through the shared selector. The path is already approved.

2. **[P2] Codex — `scripts/lib/node-runtime.sh:16`; Cursor — `scripts/lib/node-runtime.sh:23` (also probes at 63 and 151); Antigravity — `scripts/lib/node-runtime.sh:23`.** Runtime discovery must leave stdin intact for the eventual coordinator invocation, including Git credential requests, lifecycle JSON, and pre-push ref records. These version probes inherit the caller's stdin. An executable Node shim that reads a line during `--version` consumes protocol input before the receiver starts. I reproduced this on all three exact selectors: a supported shim receiving `first line\nsecond line\n` forwarded only `second line\n` to the eventual callback. Claude forwarded both lines because its probe redirects stdin from `/dev/null`. A focused regression should use a probe that attempts to read stdin and assert byte-for-byte delivery to the final receiver; ordinary native Node probes do not expose this defect.

3. **[P2] Claude — `scripts/lib/node-runtime.sh:37`; Cursor — `scripts/lib/node-runtime.sh:35`; Antigravity — `scripts/lib/node-runtime.sh:47`.** The selected plan requires rejection of malformed version output before starting coordinator code. Claude's parameter extraction does not require two separators: `v26` becomes `26.26.26`, and `v26.0` becomes `26.0.0`. Both were accepted with exit 0 by the exact selector. Cursor, Claude, and Antigravity also accepted `v026.0.0`; Antigravity explicitly removes the invalid leading zero. Thus malformed probes can authorize execution instead of failing before build/CLI dispatch. Parameterize incomplete components and leading zeroes alongside the existing prerelease/malformed cases. Codex rejected all three malformed outputs in the same reproduction; all four accepted `v26.0.0` and rejected `v26.0.0-rc.1`.

4. **[P2] Cursor — `scripts/lib/node-runtime.sh:131` (the diagnostic loop at 75 has the same expansion).** PATH components are literal directory names, and discovery must preserve their order without pathname expansion. `for dir in ${PATH-}` performs glob expansion after splitting. With PATH naming an existing `.../node[1]` directory and a sibling `.../node1` also present, the selector chose `.../node1/node`, although that directory was not on PATH. The other three selectors chose the literal `.../node[1]/node` in the same fixture. Add this literal-bracket case to the existing wrapper/selector fixture; disabling glob expansion during splitting or using literal component extraction addresses the failure.

5. **[P2] Cursor — `test/hookSync.test.ts:581`.** A digest regression must mutate a disposable install fixture, because the system suite runs multiple files against the same repository installation. This test temporarily rewrites the live `scripts/lib/node-runtime.sh` in `repoRoot`. A concurrent install/inspection can hash the temporary comment, then compare against the restored file and report false hook drift; interruption can also leave the source modified. This is a static concurrency finding, not a suite failure observed in this review. The other implementations already demonstrate the appropriate existing-fixture approach: copy the canonical sources, alter the fixture selector, and compare its digest.

**Coverage and reuse**

Codex's existing wrapper fixture checks PATH/nvm/override selection together with selected build Node, product-child Node, caller cwd, spaces, and arguments. Its installed-hook test exercises both shim/vendor modes with unavailable coordinator Node, failing product checks, and passing product checks. The credential test executes the actual rendered helper. Its bootstrap environment test intercepts pnpm children without invoking dependency installation. Those are useful boundaries to retain when fixing findings 1 and 2.

Claude and Antigravity extend actual setup-trust execution under old ambient Node, which Codex should adopt. Both also exercise installed shim/vendor hooks under an old product PATH and hash a disposable selector copy. Claude's `/dev/null` probe isolation is directly reusable. Antigravity's selector has more parsing/comparison machinery, including leading-zero normalization that should instead reject malformed output; its hook bridge resolves once for validation and again for execution. Neither extra behavior is needed for the issue.

Cursor's coverage is less decisive: `test/githubAuth.test.ts:114` executes a separately constructed Node command rather than the generated credential helper; `test/hookSync.test.ts:600` sources the policy and directly runs the selector rather than exercising installed verification with a failing product check. Its bootstrap tests cover rejection of an old Node but not successful selection of a different runtime for installation. Its engine-consistency test at `test/wrapper.test.ts:220` compares `.nvmrc` and `package.json`, without checking the selector's hard-coded floor. These limitations should not be mistaken for demonstrated integration coverage.

Codex deliberately renders callbacks through the shared selector. Cursor, Claude, and Antigravity render the generating process's absolute Node executable, consistent with the selected plan's disclosed tradeoff. Their documentation explains regeneration after deleting that Node installation. Codex avoids that operational dependency and keeps one selection policy for saved callbacks, at the cost of a probe on each invocation; its probe must therefore preserve stdin. This is a design comparison, not an additional finding against the documented pinned-executable approach.
