# Issue 118 peer plan review

Reviewed the plans pinned at Cursor `25a7ff8bc81c90389f203c95579dddcf3a2b5387`, Codex `492f35f7e088821f91ba27893ce702c35bb7339f`, and Claude `2dcc50606a58b412c4b6f527e39f578defb39456`.

## Findings

1. **Cursor plan, “Cursor tokens” / `src/agentEvent.ts` claim:** the plan says the existing extractor and hook rows provide the token path, and proposes adding `actionId` to `agent-usage` rows rather than changing the read-side token shape. **Rule:** hook-supplied tokens must survive the exact normalize → journal → analytics-reader round trip, and absent data alone may be labelled unavailable. **Concrete failure:** `normalizeCursorUsageEvent` persists canonical `{input, output, cacheRead, cacheWrite, reasoning}` counters, but `cursorUsageFromJournalDetails` reparses them with vendor-only aliases and drops `tokens`; adding `actionId` does not repair that loss, so real Cursor sessions continue to report no tokens and the roster total remains unavailable. **Smallest correction:** adopt Claude’s canonical-token reader before the existing vendor-alias fallback, then separately change the no-token coverage label to `unavailable`.

2. **Codex plan, `src/cursorHookUsage.ts` claim:** the plan changes only the no-record label to `unavailable` and assumes current Cursor capture already reaches aggregation. **Rule:** a coverage-label fix must not conceal a broken measurement path; persisted normalized counters must be read as measured counters. **Concrete failure:** following the plan exactly still discards every canonical token object written by `agentEvent.ts`, so its proposed mixed Cursor/Codex complete-roster test cannot pass using the production hook round trip (only the existing vendor-shaped test data passes). **Smallest correction:** add a round-trip regression from `normalizeCursorUsageEvent` through `cursorUsageFromJournalDetails`/`readCursorHookUsage` and implement canonical-shape parsing as in Claude’s plan.

3. **Codex plan, `src/transcriptRead.ts` task-boundary attribution claim:** the plan assigns token rows to a transcript `task_started.turn_id` and then relies on the current action-turn match. **Rule:** phase attribution must distinguish multiple coordinator actions that share one vendor turn, and any ambiguity fallback must remain explicit rather than becoming exact coverage. **Concrete failure:** the current aggregator uses `agentTurns.find` for an exact `(sessionId, turnId)` match; when Codex reuses one turn id across nested actions in different phases, every newly turn-labelled token row selects the first action, silently moving later-action cost to the earlier phase and potentially preserving `complete` coverage. **Smallest correction:** incorporate Claude’s shared-vendor-turn rule: among matching action windows with one session/turn identity, use the latest started matching action only as a labelled `partial` fallback; keep matches across different turn ids unassigned.

4. **Cursor plan, “Codex attribution” claim:** the plan says `src/transcriptRead.ts` will join through coordinator `prompt-submitted` → `stopped` windows, but does not define how repeated windows with the same vendor turn are resolved. **Rule:** the plan must place the join where both transcript records and journal windows are available and must specify a deterministic, coverage-preserving ambiguity rule. **Concrete failure:** `transcriptRead.ts` receives only vendor/session/root and cannot inspect journal windows; leaving the current `matching.length === 1` logic in `analytics.ts` unchanged preserves the measured shared-turn unassigned volume, so the representative-attribution acceptance case still fails. **Smallest correction:** keep transcript parsing vendor-local and put the shared-turn window selection in `analytics.ts`, with a test for same-turn nested windows and a sibling test proving different-turn overlap remains unassigned.

5. **Claude plan, legacy CLI branch claim:** the plan reports legacy state from the start header with `activeRoster = originalRoster` and deliberately does not read `cursors.json`. **Rule:** legacy analytics is authorized only for completed read-only runs, and roster totals/waits must use the run’s active roster rather than agents that were dropped. **Concrete failure:** an unfinished format-2 run is accepted by the analytics branch, while a completed run that dropped an agent includes that agent again; the latter can suppress an otherwise valid cross-roster total and adds wait/coverage rows for a non-active participant. **Smallest correction:** add a loose read-only cursors header containing `formatVersion`, `completed`, and `activeRoster`; require `completed: true` and pass that recorded roster without exposing the header to operational readers.

6. **Claude plan, `readJournalForAnalytics` claim:** the plan skips and counts any legacy journal line that fails the current schema, including malformed rows of a known event type. **Rule:** read-only compatibility may tolerate explicitly reported unknown event kinds, but it must fail rather than publish trustworthy-looking timing when a known load-bearing event is malformed. **Concrete failure:** if a format-2 terminal `gate-advanced` row has an invalid timestamp or shape, skipping it makes a completed run appear in progress and extends its elapsed/final phase duration to the current time; a provenance count does not make those headline numbers valid. **Smallest correction:** skip only unknown legacy event types with the visible count, fail on malformed known events, and require the completed fixture’s terminal boundary before reporting complete-run timing.

## Conclusion

Claude’s plan is the strongest basis because it identifies and tests the actual Cursor canonical-field loss and the real Codex shared-turn ambiguity rather than only changing labels or adding unrelated identity. It should be selected only with the two legacy-reader corrections above: read `completed` and `activeRoster` through a minimal read-only cursors header, and fail on malformed known journal events instead of calculating plausible but wrong timing. The Cursor and Codex plans both miss the production Cursor round-trip defect; their Codex attribution proposals also need Claude’s explicit shared-turn fallback to avoid leaving records unassigned or silently assigning them to the first action.
