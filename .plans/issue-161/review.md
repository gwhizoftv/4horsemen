## Findings

1. **Claude — Reuse and Scope / item 6 (`n` → `restartOwnerAction`).** The plan claims interactive `n` should call the extracted `restart-action` mutation so “a fresh `action.md` is issued,” while “uncommitted work in the agent clone is untouched.” The rule that must hold: `n` answers the issue’s stuck case (agent drafted work but has not published; coord still thinks it is working) by reminding or re-delivering the *current* outstanding action, without replacing that action. Failure if followed as written: `clearAgentLocalWork` deletes the live `action.md` / completion / response files and `replaceCursor` clears `actionId`, then the loop issues a new action; the agent mid-draft is not nudged to finish the same task and may be re-prompted from scratch. Smallest correction: bind `n` to a same-action reminder through existing delivery/nudge guards (cursor / antigravity / codex), and keep `restart-action` as the separate CLI for intentional reissue.

2. **Cursor — Alternatives Rejected / recovery `--coord-root` (issue 4d).** The plan treats printing `--coord-root` on recovery lines as sufficient and rejects defaulting global resolution. The rule that must hold: issue 4d requires recovery directions that work when the owner omits `--coord-root` from an onboarded repository worktree (same convenience `coord N` already has). Failure if followed as written: `existingContext` still routes flagless resume through `context()`, which requires `--coord-root`, so the owner pastes or retypes `coord resume --issue … --reset-nudge-budget` from the onboarded folder and still gets a cryptic missing-root error. Smallest correction: default `existingContext` from an onboarded `io.cwd` when neither `--product` nor `--coord-root` is set (as claude / antigravity / codex plan), *and* keep a quoted `--coord-root` on printed recovery for copy-paste from elsewhere.

3. **Antigravity — Alternatives Rejected #4 (interactive nudge-loop release).** The plan rejects “requiring `--reset-nudge-budget` in interactive hold release” because the operator already inspected the agent, without stating that `releaseHold` still receives `resetBudget: true`. The rule that must hold: `releaseHold` in `src/state.ts` throws on nudge-loop unless `resetBudget` is true; interactive `r` must satisfy that invariant, not delete it. Failure if followed as written: an implementer calls `setOwnerPause(..., { hold })` without `resetBudget` and `r` still fails with “Nudge-loop release requires --reset-nudge-budget,” or they weaken `releaseHold` and bypass the send-budget safety the CLI documents. Smallest correction: after confirm, pass `resetBudget: true` for `reason === "nudge-loop"` only (same mutation as the CLI flag).

4. **Antigravity — Tests / status indicators (Unicode `✓` / `⚠`).** The plan’s issueReport tests require those symbols as the good-vs-intervention cue. The rule that must hold: status must stay unambiguous when stdout is redirected, logged, or viewed on a limited terminal (issue also asks for a leading character *or* color; ASCII words suffice). Failure if followed as written: piped/captured status loses or garbles the only severity signal, and grepping logs for intervention becomes brittle. Smallest correction: use ASCII labels such as `[OK]` / `[ACTION]` or `OK` / `NEEDS YOU` (claude / codex).

5. **Codex — Exact File List / Reuse (schema and module expansion).** The plan changes `src/agentLifecycle.ts` (new Stop-observation fields), `src/doctor.ts` (extracted startup inspection), `src/tmux.ts` (session env diagnostic), and `src/verificationRunner.ts` (progress callback API) for items that peer plans solve with runLoop logs and in-memory counters. The rule that must hold: stay within the issue and make the smallest change that fully solves it; justify every expansion of persisted/advisory schema and delivery-adjacent surfaces. Failure if followed as written: implementation grows a lifecycle schema + tmux/verification API surface for advisory UX, raising regression risk around observation authority and review thrash versus a display/logging-only fix. Smallest correction: keep Stop/hook warnings and progress as runLoop/cli logging (and call-site announcements) unless a later amendment proves durable fields or a verification callback are necessary; retain codex’s stronger rules on same-action `n`, idle proof, and quoted `--coord-root`.

6. **Claude — Out of scope / docs.** The plan excludes README/docs rewrites (“only `--help` is” requested). The rule that must hold: owner vocabulary changes (pin→commit, product→repository, `/steer`, nudge-loop) must not leave `docs/coord-driver.md` teaching the old jargon while the CLI teaches the new. Failure if followed as written: operators who follow the driver doc still see “pin” / “product” / unexplained holds and distrust the new status text. Smallest correction: add `docs/coord-driver.md` to the file map (cursor / codex), limited to the glossary and control sections this issue changes.

## Conclusion

None of the four plans is safe to implement unchanged. The blocking disagreements are: Claude’s `n`→`restart-action` mapping (wrong for the drafted-but-uncommitted case), Cursor’s missing onboarded-cwd default for resume/status context (incomplete 4d), Antigravity’s ambiguous nudge-loop budget reset and Unicode-only severity markers, and Codex’s oversized schema/module expansion for advisory UX. A selectable plan should combine: plain-language status with ASCII severity and `----` framing; quoted recovery commands plus cwd defaulting for `--coord-root`/`--product`; same-action guarded `n` (not restart); confirmed `r` with `resetBudget: true` on nudge-loop; start hook warnings and progress logs without new workflow authority; repository wording in help/errors (optional `--repository` alias is fine; renaming the flag is not); and a narrow `docs/coord-driver.md` update.
