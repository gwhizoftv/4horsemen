# Plan review — issue 176 (bound pins claude 7fa11abb, codex d039ad6d, cursor d1bf5b90)

## Findings

1. **Cursor plan (`d1bf5b904a25b5372904fbec43faac67df8c0220`), Approach / `orderAgentAction` clear to `idle`.** The plan claims that after `workflowCompleteAt`, the next `orderAgentAction` should rewrite inherited `working`/`queued` to coordinator-authored `idle` (bump `idleEpoch`, clear `turnId`). Rule: `docs/readiness-policy.md` (“Quiet work is normal”) forbids fabricating execution state from non-vendor evidence, and hooks alone authorize duplicate-send eligibility after the first successful send. Failure if followed as written: lifecycle would report a Stop that never happened; any later path that trusts `execution === "idle"` (including `decideLifecycleNudge` after inject) would treat a missing-Stop agent as hook-idle, and clearing `queued` would also drop a real pending-input/background encoding that `stopped` itself preserves as `queued`. Smallest correction: do not rewrite `execution`; keep a first-send-only delivery exception (as in the claude / codex plans) keyed on workflow-complete + never-sent successor, leaving hook-derived state intact.

2. **Cursor plan, Codex readiness left unchanged.** The same plan relies on the order-time clear so `deliver` no longer early-returns on `working`, while `harnessPromptReadiness` `case "codex"` still returns ready unconditionally (`src/tmux.ts` ~180–182) with no turn-chrome veto. Rule: scrape is a veto for in-flight turns; a false send into a live turn is worse than a false stall. Failure if followed as written: after clearing stale `working`, the next nudge can type into a Codex pane that still shows live chrome such as `• Working (… esc to interrupt)` because Codex is always “ready.” Smallest correction: pair any recovery path with a Codex turn-chrome (and preferably dialog) veto before keystrokes, as both peer plans require.

3. **Cursor plan, lost-delivery extension for `working` + `turnId === null`.** Claimed as defense in depth for uncorrelated injections. Rule: after a matching `UserPromptSubmit`, `applyLifecycleObservation` sets `action.turnId` when the action id/digest match, so the common stuck-`working`-after-accept case never meets `turnId === null`. Failure if followed as written: the primary gate-advance stall (next action never sent) is not exercised by this branch; implementers may believe the stall is covered when only the rare uncorrelated path is. Smallest correction: treat lost-delivery hardening as optional and secondary; the mandatory acceptance test must be “prior action workflow-complete, no Stop, next action still `ordered`/`injectedAt === null`, exactly one successful first send.”

4. **Claude plan (`7fa11abb8c9f49ae44bf9891bd9e9933024bb612`), first-send override via `requireIdleSentinel`.** Claim: before the first send, positive tail `COORD-IDLE` (Codex-aware) may overrule lifecycle `working` without rewriting lifecycle. Rule: readiness policy already states that an action still at `delivery: "ordered"` has nothing to duplicate and may be retried when scrape is ready; hooks authorize duplicates only after a successful send. Failure if the plan is *not* followed and today’s `deliver` guard stays absolute: gate advance still silently skips the initial nudge whenever Stop was missing, which is the issue-170/176 symptom the plan cites. This finding is supportive: the approach matches the stated policy exception surface better than fabricating `idle`. Residual risk to mitigate in implementation (not a plan defect): the Codex trailing-line allowlist and `codex-turn-chrome` regex must stay fail-closed on unknown UI so the override never types into app-server / approval modals (#174).

5. **Codex plan (`d039ad6d99dded4c7188eb3558d64f8889683046`), scope across launcher, schema, protocol, and reports.** Claim: fix the stall by combining `--no-daemon` launch isolation, a new completed-turn lifecycle record, strict Codex prompt evidence, issue-report copy, and bounded double re-read of `action.md` in `src/action.ts` + `templates/product/AGENTS.protocol.md`. Rule: keep the work within the issue and make the smallest change that fully solves it; justify every expansion. Failure if followed as written: the stall is solvable without a new lifecycle field, without changing every agent’s post-complete protocol latency, and without coupling product acceptance to an owner-supervised real-harness canary and CLI help-text capability probe; the file map (~14 paths) and canary gate inflate review/regression surface and can block merge on operator steps the coordinator does not own. Smallest correction: keep the first-send exception + Codex scrape vetoes; move `--no-daemon` / app-server isolation and protocol multi-reread to a follow-up (or docs-only) unless implementation proves the delivery exception alone cannot recover.

6. **Codex plan, bounded agent re-reads as a #174 fix.** Claim: wait one second and reread twice after completion before printing `COORD-IDLE`. Rule: after the final reply the agent cannot monitor later `action.md` changes without another trigger (issue 176 text; claude/cursor alternatives correctly reject polling as primary delivery). Failure if followed as written: every Git and response action pays fixed delay even when the coordinator has not yet published the successor; missing Stop still blocks the *next* nudge unless the delivery exception lands, so the rereads do not replace coordinator recovery. Smallest correction: omit protocol/`action.ts` reread changes from this issue’s file map; keep the single existing pre-`COORD-IDLE` re-read.

7. **All three plans, reuse / new files / tests.** Claude and Cursor create no product files and extend existing `test/tmux.test.ts` / `test/runLoop.test.ts` (Cursor also `test/agentLifecycle.test.ts`). Codex creates none but spreads tests across six suites including launcher execution. Rule: prefer extending existing tests; justify every new abstraction. Failure if Codex is implemented as written without trimming: install/launcher and protocol tests become load-bearing for a nudge-gate bug, so a launcher help-text false negative can fail the issue unrelated to Stop recovery. Smallest correction: require the focused deliver/lifecycle/tmux regressions first; treat launcher/protocol tests as optional only if those files remain in scope after trimming.

## Conclusion

Select the **claude** plan (`7fa11abb8c9f49ae44bf9891bd9e9933024bb612`) as the implementation basis: it correctly diagnoses silent `deliver` + `decideLifecycleNudge` gating on stale `working`, keeps Stop observational, avoids fabricating lifecycle idle, and adds the Codex sentinel / turn-chrome scrape fixes required for a safe first-send exception—aligned with readiness policy’s “ordered ⇒ nothing to duplicate” rule.

Reject the **cursor** plan’s order-time rewrite of `execution` to `idle` (fabricates vendor state; unsafe on always-ready Codex without chrome vetoes). Reject the **codex** plan as the primary map because `--no-daemon`, completed-turn schema, protocol double-reread, and canary coupling are larger than needed; salvage only its insistence on fail-closed Codex prompt evidence and first-send-only scope if merging details into the claude approach.

Within the issue (#176 + #174 missing-nudge / missing Stop): yes for all three diagnoses. Smallest complete product fix: claude’s delivery exception + Codex scrape hardening. App-server / hook-trust remain operator concerns named in logs/docs, not additional product schedulers.
