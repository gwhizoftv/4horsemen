## Comparison

The bound implementations are Antigravity `ec03d8e6a235294a16ef26cea55ee940d1ee1b73`, Cursor `d89f2d6d61c268714e5a1065098dd235d284cc3e`, Claude `c2784bf31651db084f00eefeb103a4daa373d602`, and Codex `fb608c5a8022b2ed7b78def20ad468fc37dd31b1`.

### Findings

1. **`scripts/lib/launcher.sh:119-125` (Antigravity), `scripts/lib/launcher.sh:53-58` (Cursor), `scripts/lib/launcher.sh:187-198` (Claude), and `scripts/lib/launcher.sh:162-167` (Codex):** the wrapper must refuse `git show` once the current action has materialized bound inputs, retaining exact `<sha>:<path>` only as the missing-packet fallback. Every implementation instead permits forty-hex blob reads unconditionally, so an agent handling a fully materialized comparison can still repeat all of the peer `git show` calls this issue is meant to eliminate. A focused wrapper test should write an action containing `## Bound input files` and expect exact pinned show to exit 2, then remove that section and expect the same invocation to delegate.

2. **`src/materializedInputs.ts:73-74,108-116` (Antigravity), `src/materializedInputs.ts:163-176` (Cursor), `src/materializedInputs.ts:181-195` (Claude), and `src/materializedInputs.ts:60-71,181-185` (Codex):** coordinator materializations exposed to a harness must be read-only and must continue to represent the bound pin. Antigravity, Cursor, and Claude leave full worktree files normally writable; Codex removes file write bits but deliberately leaves every directory `0700`, allowing an agent to unlink or replace a read-only file. Cursor's `0555` packet directory is likewise beneath the writable granted `inputs/` parent and can be renamed and replaced. Thus none of the four delivers immutable, read-only worktrees through the writable `--add-dir` grant. The smallest acceptance test is an agent-context attempt to overwrite, unlink, rename, and `chmod` a materialized file; all operations must fail while coordinator teardown must still succeed.

3. **`scripts/lib/launcher.sh:97-111` (Antigravity) and `scripts/lib/launcher.sh:34-45` (Cursor):** automated-mode `status` and `diff` must remain blocked when ordinary repository selectors still target the managed clone. Both wrappers immediately delegate on `-C`, `--git-dir`, `--work-tree`, `GIT_DIR`, or `GIT_WORK_TREE`, so `git -C . status` and `git --git-dir .git diff` succeed in the exact clone the coordinator owns. Claude and Codex resolve selectors and correctly distinguish the managed clone from fixture repositories.

4. **`src/materializedInputs.ts:68-70` (Antigravity) and `src/materializedInputs.ts:153-192` (Claude):** every bound blob/worktree must materialize successfully before an action listing filesystem alternatives is published. Antigravity silently skips a missing blob, while Claude records missing documents and failed worktrees in `omitted` and continues; either path publishes an action without the promised direct input and pushes the agent back to Git. Claude's test named `omits an unreadable document instead of failing preparation` codifies the acceptance failure. Cursor and Codex throw instead.

5. **`src/runLoop.ts:1381-1395` (Antigravity), `src/runLoop.ts:1394-1408` (Cursor), and `src/runLoop.ts:1424-1438` (Claude):** every rewrite or reissue of an action with bound inputs must retain its exact materialized paths. These three reissue paths call `buildOrder` without rematerializing or passing `materialized`, so a verification rejection rewrites the action and erases `## Bound input files`; the retry then lacks the direct paths even though the initial action had them. Codex rematerializes and passes the descriptors in its reissue path.

6. **`src/materializedInputs.ts:108-116` (Antigravity), `src/materializedInputs.ts:181-195` (Claude), and `src/materializedInputs.ts:178-185` (Codex):** an existing `<agent>-<sha8>` worktree must have `HEAD` equal to the full bound forty-character SHA before reuse. These implementations accept any existing directory, so an eight-character collision or stale partial materialization can make an action label the wrong product tree as the authoritative pin. Cursor alone verifies `rev-parse HEAD` both before reuse and after creation.

7. **`src/runLoop.ts:880-887` (Cursor):** superseded worktrees must be pruned when a step's bound set no longer contains their pins. Cursor invokes pruning only when the new action itself contains a pin, so transition from implementation comparison to a markdown-only ballot retains every old implementation worktree until wipe. The prune call should run for an empty keep set as well.

8. **`githooks/post-merge:52-71` (Antigravity) and `githooks/post-merge:52-60` (Cursor):** an existing coordinator-managed wrapper must be refreshed when its canonical template changes, while foreign files must be preserved. These hooks regenerate only when the file is absent, so an installed clone keeps obsolete blocking/delegation behavior after an upgrade. Claude and Codex render a candidate, replace a stale managed wrapper, and leave foreign bytes alone.

9. **`src/materializedInputs.ts:51-64` (Antigravity) and `src/materializedInputs.ts:99-116` (Claude):** a content-addressed packet may be reused only after its manifest identity and every entry digest are checked against the current bound set. Antigravity trusts any parsed `entries` array and Claude checks only that each recorded path exists, so a damaged or replaced packet is silently presented as verified peer input on later actions. Cursor verifies recorded hashes; Codex additionally verifies containment and exact expected identities, making its reuse boundary the strongest.

### Scope, reuse, and coverage

All four implementations stay within the issue's approved product surface: each changes the same 19 implementation/test paths, adds only the justified `src/materializedInputs.ts`, extends the four existing test files, and adds no dependency or version-only churn. All reuse `BareMirror.readBlob`, `materializeWorktree`/`removeWorktree`, `deriveBoundInputs`, `buildOrder`/`writeAction`, contained runtime paths, and the shared launcher template rather than creating parallel abstractions.

Antigravity is the smallest diff and its tests exercise wrapper delegation, packet hashing, pruning, and wipe, but they miss same-clone selector bypass, strict missing-input failure, manifest validation, reissue preservation, and worktree pin verification. Cursor is similarly compact but has the narrowest wrapper coverage—the new install test checks rendered bytes rather than executing refusal cases—and its conditional pruning gap is untested. Claude adds the broadest named wrapper/post-merge and materialization tests, but also the most code and commentary; more importantly, its tests intentionally preserve omission-on-failure and do not cover reissue path retention or immutable worktrees. Codex has the most complete end-to-end policy coverage: it tests same-clone selectors versus other repositories, validates packet contents and identities, preserves materializations on reissue, refreshes managed wrappers, and prunes on empty keep sets. Its focused tests still fail to probe post-materialization show blocking, replacement through writable directories, or wrong-HEAD reuse.

### Conclusion

No bound pin satisfies issue 124 unchanged because all four leave exact pinned `git show` enabled after materialization and none provides genuinely read-only worktrees through the writable grant. Codex `fb608c5a8022b2ed7b78def20ad468fc37dd31b1` is the closest revision baseline: it avoids the selector, missing-input, reissue, stale-wrapper, pruning, and manifest-validation failures present in the alternatives. It still needs the common show/immutability fixes plus full-SHA verification before reusing an existing worktree. Cursor has the best worktree-HEAD verification but needs more wrapper, lifecycle, and reissue correction; Claude has the next-best wrapper/install lifecycle but weakens fail-loud and packet-integrity guarantees; Antigravity has the largest set of correctness gaps despite its smaller diff.
