# Review — issue 256 plans

Bound pins reviewed: muse `46547e48ade505e871e4de91ceb06895151a4b1a`, claude `6630d4b4bd3ce2c16d578ee2a70bf356055d0637`, codex `0155280a858a776d3e8db3acc00c87f5bddcc6cc`. Issue baseline: `d646aedcc21a43dde942c86c65b64aba649c1964`.

## Findings

1. **Plan claim (muse, Exact File List / `src/hookPolicy.ts` + `src/cli.ts`):** the required-artifact guard returns an immediate local error at pre-push when the outgoing tree lacks `requiredPath`, and at pre-commit when the artifact is untracked or unstaged. **Rule that must hold:** the guard must not break the existing two-step publication flow, in which `R4.implement`/`R6.revise` legitimately commit and push product work before the `implementation-ready` signal at `requiredPath` exists (a plan-amendment request at that same path, with unrelated product edits left unstaged, must also still work). **Concrete failure if followed as written:** an implementer’s first product commit is blocked at pre-commit because the signal file is still untracked, and every intermediate product push is blocked at pre-push because the pushed tree has no signal yet; the workflow the guard protects can no longer publish incrementally, so correct agents are stalled instead of premature-`complete` writers. **Smallest correction:** exempt an absent signal (absent from worktree, index, and outgoing tree) on `R4.implement`/`R6.revise` intermediate pushes, as the codex plan specifies, or downgrade to the claude plan’s non-blocking warning; never block solely because a not-yet-created signal is missing.

2. **Plan claim (muse, Exact File List / `src/runLoop.ts`):** the watchdog worktree stamp combines the `.git/index` stamp with a hash of `git status --porcelain` run by the coordinator every minute. **Rule that must hold:** the watchdog’s own observation must not manufacture the activity it measures; a genuinely stalled agent must still earn its one resend and one `[WAIT]`. **Concrete failure if followed as written:** `git status` opportunistically refreshes `.git/index`, so the coordinator’s own probe keeps changing the index component of the fingerprint; `quiet` in `watchOwedWork` (`src/runLoop.ts:2079-2082`) never holds, and a truly stalled, hookless agent is never resent and never reported — the opposite failure to the one in the issue, and silent. **Smallest correction:** enumerate with `git ls-files --modified --others --exclude-standard` (which does not rewrite the index), as the claude plan specifies, and do not include metadata that the probe itself refreshes.

3. **Plan claim (muse, Exact File List / `src/runLoop.ts`):** `harnessPromptReadiness` not-ready reasons such as `antigravity-turn-chrome` and `claude-usage-wait` count as vendor-busy activity even when `paneActivityDigest` is unchanged. **Rule that must hold:** busy evidence must indicate live work; `harnessPromptReadiness` (`src/tmux.ts:282`) is a keystroke-safety check, not idle detection, and its reasons include waiting states. **Concrete failure if followed as written:** a crashed turn that leaves static turn chrome on screen, or a usage-wait pane, is treated as active forever; the quiet window never closes, so the one resend that recovers a lost prompt is suppressed indefinitely for exactly the hookless agents this issue is about. **Smallest correction:** use a narrow busy predicate over live status chrome (codex plan, `src/tmux.ts` parsers), exclude wait/no-prompt reasons, and require the busy signal to be corroborated or time-bounded rather than sufficient on its own forever.

4. **Plan claim (claude, Exact File List / `src/cli.ts` and Conclusion):** the pre-push diagnostic is deliberately non-blocking — `coord prepush: WARNING` on stderr, exit code unchanged. **Rule that must hold:** issue requirement 1 asks coord to “surface an immediate local error” when the required artifact is untracked or uncommitted, so the premature-`complete` path is actually interrupted, not merely annotated. **Concrete failure if followed as written:** an agent that does not read hook stderr (the normal case when hook output scrolls past in the pane) pushes, writes `complete` with the bad SHA anyway, and `evaluateEvidence` (`src/evidence.ts:274`) rejects with `required artifact … is missing` — the exact nudge cycle the issue exists to eliminate, now with an unread warning attached. **Smallest correction:** block (nonzero exit) for the cases that cannot be legitimate — artifact present but dirty/untracked, or missing from the outgoing tree on non-implementation steps — while warning or exempting the absent-signal intermediate push from Finding 1; the codex plan’s split is the working model.

5. **Plan claim (claude, Exact File List / `src/hookPolicy.ts`):** `requiredArtifactWarning` “returns `null` in every other case, including any thrown error”, and (in `src/runLoop.ts`) `cloneActivityStamp` caps the changed-path list at 256 and returns `"none"` on any error. **Rule that must hold:** a guard/watchdog must not silently pass in precisely the degraded states it was added for; unresolvable or truncated observation is “unavailable”, not “nothing to report”. **Concrete failure if followed as written:** a malformed or mismatched current `action.md` on an active run produces no warning and no diagnostic, so the premature-`complete` failure recurs invisibly; likewise a clone with more than 256 changed paths, or an `ls-files` timeout, yields a constant stamp while the agent edits file 257, and the false `stalled` resend from #238 recurs. **Smallest correction:** surface a bounded diagnostic for malformed/mismatched actions on an otherwise established active run, treat truncated or failed enumeration as unavailable (never as a complete quiet sample), as the codex plan requires.

6. **Plan claim (muse, Tests §2):** pre-push guard cases join `test/cli.test.ts` around the existing `hook-verify` case (`test/cli.test.ts:2335`). **Rule that must hold:** regression tests must exercise the real installed-hook path and the runtime binding (start state, cursors, current `action.md`) that the guard depends on. **Concrete failure if followed as written:** the `test/cli.test.ts` hook-verify fixture is a bare clone without an active coordinator run, so the new cases either degenerate into the guard’s no-op path (passing while testing nothing) or require rebuilding the `installed`/`activeRun`/`stageWork` fixtures that already exist in `test/hookSync.test.ts`, duplicating them in the wrong suite and config (`vitest.config.ts` instead of `vitest.system.config.ts`). **Smallest correction:** put the guard cases in `test/hookSync.test.ts` under `coordinator verification binding`, as both peer plans specify.

7. **Plan claim (codex, Reuse and Scope / Watchdog activity):** the fingerprint also observes `run-*.log` files under `agentRuntimePaths(...).terminalLogs` and an unchanged vendor busy line resets the quiet baseline on every observation. **Rule that must hold:** watchdog inputs must be agent activity, bounded and incapable of self-sustaining; coordinator-owned logging must not count as the agent working. **Concrete failure if followed as written:** raw terminal logs are written by the coordinator’s own tmux capture of the pane, so coordinator output (including its own resend text echoed in the pane) can feed the activity stamp, and a static busy line left by a crashed turn suppresses resend/`[WAIT]` indefinitely — the plan’s own tests only cover busy-then-idle, not stuck-busy. **Smallest correction:** drop the terminal-log input (transcript + clone stamps already cover the #238 Antigravity case, since that agent was editing its clone), or prove in a test that coordinator-written log growth cannot reset quiet; add one stuck-busy test showing recovery still happens.

8. **Plan claim (codex, Exact File List):** nine files change, including a new busy predicate in `src/tmux.ts` plus `test/tmux.test.ts`, on top of the action text, guard, and watchdog work. **Rule that must hold:** keep the work within the issue and make the smallest change that fully solves it; every additional surface needs justification against existing reuse. **Concrete failure if followed as written:** the `src/tmux.ts` predicate is the one genuinely new abstraction, and if its prose-rejection fixtures are wrong it silently reclassifies idle panes as busy (or vice versa) for the nudge path that shares those parsers — a regression vector the other two plans avoid by reusing `paneActivityDigest`/`harnessPromptReadiness` as-is. The rest of the codex map is well justified (cursor-bound action identity, non-`HEAD` outgoing SHA, malformed-action diagnostics, local and coordinator verification modes, amendment-request flow — none of which the muse or claude plans fully specify). **Smallest correction:** keep the nine-file map but land the `tmux` predicate watchdog-only, with the positive/negative fixtures the plan already names, and do not reuse it for delivery decisions in the same change.

No finding against the shared core all three plans agree on: the `renderGitAction` wording change in `src/action.ts` (push must succeed, pushed tree must contain `requiredPath`, before `complete`), keeping `src/evidence.ts` as the coordinator authority, creating no new product files, and adding focused failing-before/passing-after tests to existing test files. All three plans stay within the issue, reuse existing code and test support, justify their file maps, and propose focused rather than broad tests; they differ on guard strength (Findings 1 and 4), probe safety (Findings 2 and 5), test placement (Finding 6), and watchdog input scope (Findings 3, 7, and 8).

## Conclusion

Approve the codex plan (`0155280a858a776d3e8db3acc00c87f5bddcc6cc`) as the base, with the corrections in Findings 7 and 8: it is the only plan that simultaneously blocks premature completion where blocking is safe, preserves the `R4`/`R6` absent-signal and amendment-request flows, binds the guard to the cursor’s current action and the actual outgoing SHA, and treats truncated or failed watchdog observation as unavailable. Fold in the claude plan’s `ls-files`-based clone stamp (Finding 2) rather than the muse plan’s `git status` probe. Do not approve the muse plan as written (Findings 1, 2, 3, and 6) or the claude plan as written (Findings 4 and 5) without those corrections. Verdict: codex plan approved with corrections; muse and claude plans revise-and-resubmit on the findings above.
