## Findings

1. **[P1] Claude and Cursor: the Flutter detector rejects valid Flutter manifests and accepts unrelated text.** Claude's Exact File List, Dart/Flutter detector (lines 30–32), uses `/^\s*sdk:\s*flutter\s*$/m`; Cursor's corresponding section (lines 20–22) uses `/^[ \t]*sdk:[ \t]*flutter[ \t]*$/m`. **Rule:** a valid Flutter SDK dependency must select the Flutter policy regardless of equivalent YAML formatting, and a description string must not select that SDK. **Failure:** each detector returns false for a dependency whose value is quoted, whose SDK line has a trailing comment, or whose mapping uses flow syntax. Cursor consequently retains the reported missing-finalization-checks error for otherwise ordinary Flutter apps; Claude incorrectly selects Dart commands, including `dart test`, for those apps. Conversely, a plain Dart manifest with `description: |` followed by the indented text `sdk: flutter` selects Flutter and requires an unrelated SDK. A focused probe using both exact proposed regexes and the installed YAML parser reproduced all four cases. Recognize the dependency mapping and add the positive/negative cases; a line regex is not sufficient to establish YAML meaning.

2. **[P1] Cursor: Python defaults unconditionally require Ruff.** Exact File List, Python commands (lines 41–44), always proposes `ruff check .` at precommit, including requirements-only and otherwise unconfigured Python projects. **Rule:** automatic support for an existing Python test environment must not require a new optional lint tool merely because a Python marker exists. **Failure:** a project with a working pytest suite and no Ruff dependency now passes policy inference but fails plain `onboard` at the existing doctor's executable check. `onboard` returns an unsuccessful doctor report and does not register the owner locator; the user must install an unrelated linter or supply the special declaration the issue is intended to make optional. Wrapped environments similarly fail their first commit when Ruff is unavailable. The proposed tests invoke `install`, which does not run doctor, so they would miss the reported onboarding failure. Propose Ruff only with evidence that the project uses it, or use the test command as the nonempty default local phase. Include one pytest-only onboarding regression with a controlled PATH.

3. **[P2] Cursor: the notice does not describe the effective policy after partial declarations.** Exact File List, `renderInferredPolicyNotice` and its installation call (lines 50–87), compares only finalization `checks` and then renders all fields from the proposal. **Rule:** the announcement must agree with the independently merged verify commands, toolchain, and critical paths that `buildWorkspaceConfig` actually writes. **Failure:** declare `verify: { precommit: [], prepush: [] }` and a custom critical-prefix list while leaving checks inferred. The equality condition still passes, so the notice claims Ruff and pytest will run in local hooks and lists the old prefixes, although the recorded local phases are empty and the prefixes differ. A probe through the existing `buildWorkspaceConfig` reproduced exactly that disagreement. Conversely, overriding only final checks suppresses the whole notice while inferred Ruff remains installed as the mandatory local gate. Render from the effective config and track inferred versus declared fields independently; test a verify-only override as well as a checks-only override.

The directory entries authorize changes anywhere under source and tests. Cursor's bound plan likewise adds `package.json`, `Cargo.toml`, numerous manifests, and synthetic filenames such as `config.checks` and `effects.changes` beyond its five intended files. The coordinator freezes those entries into the approved map, so neither artifact enforces its claimed small scope. Put detailed marker/command explanations under Reuse and Scope, keep the file-list sections limited to intended paths, and validate the extracted set exactly. Codex's bound plan extracts exactly its eight listed files and does not have this finding.
