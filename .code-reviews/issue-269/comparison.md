## Comparison

I recommend Codex `c16f985990d637db91a10d2be26d4bbe8f944559` as the revision base. It covers direct account-only installs, preserves the original author settings of adopted clones, and keeps two issues on different accounts from changing each other's worktree author. Two reproduced failures still need a revision.

### Findings

- **All three candidates** — `src/setupWorkspace.ts:678` (Antigravity), `src/setupWorkspace.ts:671` (Claude), and `src/setupWorkspace.ts:655` (Codex). Onboarding must configure the identity Git actually uses in an adopted clone. All three read and write the repository-local author keys. A pre-existing worktree-specific author takes precedence. In an isolated Git checkout I set a worktree identity, applied the SoundSplore settings with the same local writes, and made an ordinary commit. The local email was `155764113+gwhizofss@users.noreply.github.com`, but both commit headers recorded `Existing <existing@example.test>`. The onboarding regression should adopt such a checkout and assert both identities from the commit.
- **Codex** — `src/mirror.ts:226`. Two issues must be able to create their first author-bound worktrees in one mirror. Both callers can observe the extension as disabled before either acquires the configuration lock. I ran two concurrent calls to the pinned `BareMirror.materializeWorktree` against a fresh mirror. One created its checkout and the other rejected with `EEXIST` before creating its checkout. Extend the two-account mirror test to start both calls together and require both commits to retain their respective authors.
- **Antigravity** — `src/install.ts:403`. A real direct installer call with a selected account must obtain its verified author even when the caller supplies only the account name. On a first install or an upgrade from account-only config, neither profile branch runs. The installer wires authentication and leaves the author unset, so the next commit can inherit an unrelated identity. The account-binding test supplies the profile up front at `test/install.test.ts:404`, bypassing this path.
- **Antigravity and Claude** — `src/mirror.ts:108` (Antigravity) and `src/mirror.ts:136` (Claude). A worktree belonging to an issue started under account A must keep A's author when the workspace switches to B. Both pins write to the mirror's shared config and add detached worktrees without an issue-specific author. The next ordinary commit in A's existing worktree therefore records B. Claude's own test at `test/mirror.test.ts:99` explicitly expects that switch. Antigravity freezes the profile in issue state, but resuming A can then overwrite the shared author used by B.
- **Antigravity** — `src/setupWorkspace.ts:706`. Uninstall must preserve an adopted clone's pre-existing local author settings. If the owner's name already matched the selected login before installation, uninstall treats equality as proof of ownership and removes it. A regression should seed a matching name before onboarding and check that it survives uninstall.
