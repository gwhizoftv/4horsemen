## Findings

1. **Antigravity plan, Tests (lifecycle case) and Exact File List (`test/agentLifecycle.test.ts`): the new `session-end` assertions are placed "after a corroborated `hook-denied` probe" with no stated ordering against the existing test body.** Rule: a planned test must pass after the fix when the existing test is edited as written. Concrete failure: the existing case (`test/agentLifecycle.test.ts` lines 65–87) mutates `probe.vendorVersion` to `"unknown"` (line 80) before the current line-85 `session-end` assertion, and `containmentCoverage` returns `unverified` for an `unknown` vendor version (line 81 pins this). An implementer who replaces or appends at line 85 without restoring the version gets `hook: "unverified"` and the planned `containmentCoverage(ended, digest) === { hook: "active", ... }` assertion fails even with the production fix applied — or silently weakens it to match. Smallest correction: state the insertion point explicitly, either before the `vendorVersion = "unknown"` mutation or with the version restored to `"1.2.3"` first, as the claude and codex plans both specify.

2. **Codex plan, Tests item 2 ("Historical policy versus active policy"): a parameterized real-disk policy fixture for `codex` and `claude` — temporary shim plus vendor hook-settings files, real binding computation, byte mutation, and file-removal variants.** Rule: propose the fewest focused tests that fail before and pass after, reusing existing fixtures. Concrete failure: the regression's contract is only "completed reports do not consult the live binding", which the existing fixture already exercises — `start()` uses root `/c`, so `containmentPolicy` returns `null`, which mismatches any probe binding exactly as mutated disk bytes would, and `test/agentLifecycle.test.ts` line 79 already pins mismatched-binding `unverified`. The disk fixture instead couples the report test to two vendor hook-path layouts (`.codex/hooks.json`, `.claude/settings.local.json` via `agentLifecycleHookPath`), `GIT_WRAPPER_RELATIVE_PATH` placement, and temp-dir teardown; a future hook-layout change then breaks this report test for reasons unrelated to issue 254, and the roster adaptation it needs (`start()`/`complete()` hardcode agent `cursor`, root `/c`, `activeRoster: ["cursor"]`) is left as "where needed", so a literal build can produce a report whose per-agent loop skips the seeded agents and whose `hook=active` assertions fail on absent lines. Smallest correction: drop the real-disk parameterization and use the existing `cursor`/`/c` fixture for the completed/live pair, keeping codex's valuable item-3 controls (missing entry, degraded health, `[ACTION]` precedence, mismatched denial/probe binding).

3. **Muse plan, Tests preamble vs. cases 3–4: the preamble states all cases "fail before the change, and pass after it", while case 3 is specified as a live control that "must pass before and after", and case 4 describes the never-probed completed cue as "still `[OK]`".** Rule: a plan's test contract must not contradict itself, because the implementer and reviewer judge the diff against it. Concrete failure: before the change the never-probed completed report renders `[WARN]` (health `unknown` feeds `uncertain`), so case 4's header assertion is new behavior, not a preserved control; an implementer following the preamble would expect case 3 to fail on the baseline and could "fix" the live control until it does, weakening the very guard that proves live issues still warn. Smallest correction: split the contract into "new-behavior cases (fail before, pass after)" and "controls (pass before and after)", and describe case 4's `[OK]` header as resulting from the fix while only its per-agent `unverified` text is preserved.

4. **Antigravity plan, Reuse and Scope: reuse is asserted by naming functions, but the plan never states that the shared `containmentCoverage` predicate and the live callers (`runLoop.reportStartup`, R1.join journal, `shellGuard` ingest) stay byte-identical.** Rule: scope exclusions that protect live behavior must be explicit when the same predicate has live and historical call sites. Concrete failure: nothing in the antigravity text forbids an implementer from "simplifying" `containmentCoverage` to ignore a `null`/mismatched binding globally, which would make every planned test pass while silently disabling mid-run policy-drift detection in `src/runLoop.ts` and probe ingestion in `src/shellGuard.ts`. The exact file list (four files) bounds this in practice, so this is a minor gap, not a blocker. Smallest correction: add one out-of-scope sentence naming those call sites as unchanged, as the other three plans do.

No finding against the claude plan's production or test design: it restores `vendorVersion` explicitly, proves the `[OK]` cue against both containment drift and degraded health, keeps a live `completed: false` regression guard, and correctly notes that the issue's `renderAgentStatusLines` does not exist at baseline. Its one-line `undefined`-binding ternary relies on `?:`/`??` grouping, which is correct as written.

## Conclusion

All four plans are implementable and stay within the issue: two production files, two existing test files, no new files, no schema change. The claude plan (`46d506425be4ec2fb9ff6207fd7276c8e7c86e20`) is the most mechanically complete and the leanest — it handles the `vendorVersion` ordering trap, covers health-driven downgrade separately from binding drift, and needs no new fixture machinery — and is the recommended base. The codex plan is equally correct on production behavior and adds the strongest negative controls, but its real-disk test fixture should be cut down to the existing `/c` fixture before implementation (finding 2). The antigravity plan has the right shape but must pin the lifecycle test's insertion point (finding 1) and state its live-scope exclusions (finding 4). The muse plan is production-equivalent to claude's but adds an unneeded helper and a self-contradictory test contract (finding 3). Verdict: proceed on the claude plan, optionally importing codex's item-3 controls.
