### Findings

1. **Muse `src/cli.ts:178`; Cursor `src/cli.ts:179` — P1: maintenance children must use coordination's Node.** Selecting the top-level Node interpreter is insufficient when an updater invokes `node`, `npm`, or another Node script through PATH. These maintenance commands execute immediately after `launcher_environment` applies the product's nvm pin, without restoring coordination's Node for maintenance children. With a Node 26 vendor script whose update checks its child Node, and a product pinned to Node 16, both candidates execute the vendor through Node 26 but its child reports `v16.18.0`; my isolated probe exits 42. Claude and Codex return `v26.1.0` and exit 0. Extend the existing maintenance fixture to assert child Node for update/version separately from the interactive launch, which must retain the product environment.

2. **Muse `scripts/lib/launcher.sh:43`; Cursor `scripts/lib/launcher.sh:64` — P2: an installed vendor reachable only through the product pin must remain discoverable as a final fallback.** Both implementations return before `nvm use` when the executable is absent from coordination's bin and the incoming PATH. A clone that previously launched its only installed CLI from the pinned Node's bin now reports “not found” and its pane exits, even though coordination's Node could interpret that CLI. My fixture with only a pinned-bin `claude` exits 1 for both; Codex and Claude find it and complete maintenance with Node 26. Test an empty coordination/owner vendor search followed by a valid pinned-bin installation.

3. **Muse and Cursor `test/install.test.ts:422` and `test/install.test.ts:954`; Claude `test/install.test.ts:423` and `test/install.test.ts:955` — P1: launcher tests must execute fixture vendors regardless of the developer's installations.** These environments prepend a fake vendor directory but leave Node discovery inherited from the host. The new resolver gives the selected Node's directory priority over that fake directory. If the developer has Claude or Codex installed beside Node 26, the account-token and launcher-grant tests can invoke that real agent instead of the capture stub, hanging or producing host-dependent side effects and failures. A harmless decoy vendor beside the selected Node is enough to expose this; it must never execute. Codex addresses this by putting a Node symlink in each relevant fixture bin and explicitly selecting it with `COORD_NODE`. The peers only adjust the launcher text assertion and do not isolate these executing fixtures.

4. **Codex `scripts/lib/launcher.sh:77`; Muse `scripts/lib/launcher.sh:51`; Cursor `scripts/lib/launcher.sh:73`; Claude `scripts/lib/launcher.sh:83` — P2: switching a Node script's interpreter must preserve required interpreter arguments and keep the selected coordination runtime.** For `#!/usr/bin/env -S node --expose-gc`, Muse, Cursor, and Claude replace the entire shebang with `node script`, dropping `--expose-gc`. My real-Node maintenance probe succeeds when directly executed, but exits 43 with `gc=undefined` under these three candidates. Codex preserves this shebang; maintenance succeeds, but interactive launch runs its `env node` through the product PATH. With a rejecting Node 16 fixture, that launch exits 42 before reaching the script. Add an argument-bearing shebang case covering both maintenance and launch; the result must retain the flag and the selected Node while leaving the interactive agent's child PATH at the product pin. Codex's current coverage deliberately exercises plain shebangs only, so it does not establish this behavior.

5. **Cursor `scripts/lib/launcher.sh:73` — P2: interpreter detection must identify Node itself, not a substring anywhere in a shebang.** The `"#!"*node*` pattern also matches a shell interpreter such as `/fixture/node-tools/sh`. A valid shell vendor wrapper is then passed to Node as JavaScript and fails before starting. My isolated wrapper executes successfully directly and through the other three candidates, but Cursor exits 1 with a JavaScript `SyntaxError`. A symlink to `/bin/sh` inside a directory containing `node` provides a focused regression case.
