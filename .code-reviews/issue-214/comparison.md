### Findings

1. **Cursor — `src/agentLifecycle.ts:737` — P1: a duplicate preceding Stop grants false idle eligibility.** A Stop belonging to the turn into which a successor prompt was queued must remain distinguishable from the successor's own completion, including repeated delivery. The first Stop clears `queuedBehindTurnId`, both turn identities, and the observed-turn history. Replaying that same Stop then enters the ordinary idle branch, increments `idleEpoch`, and makes `decideLifecycleNudge` return `send` while the successor can still be working. Reproduction: accept B with the live turn ID T; apply Stop(T) twice. The first result is working; the second is idle/send. Claude and Codex keep working for both deliveries. Extend the existing same-turn test with this exact duplicate, rather than only testing a distinct second Stop.

2. **Claude — `src/agentLifecycle.ts:619` — P1: any different Stop is mistaken for the queued work's completion.** After the preceding turn stops, a terminal event already known to belong to an older turn must still preserve the successor's activity. `queuedWorkStop` only requires a different ID and `queuedBehindStopped`; it bypasses the older-turn test. Reproduction: observe older turn O, then live turn T; accept B queued into T; receive Stop(T), followed by a delayed Stop(O). This pin clears the guard, records idle, advances the epoch, and returns send for B. Codex preserves working. The required regression must include an already-observed older ID after the preceding Stop, alongside the valid distinct successor completion case.

3. **Claude — `src/agentLifecycle.ts:616`; Cursor — `src/agentLifecycle.ts:636` and `src/agentLifecycle.ts:718` — P1: failed Stops bypass queued-turn protection.** The preceding turn's successful and failed terminal callbacks must both preserve queued successor work and must not bind its failure to that successor. Both queued-turn guards apply only to `kind === "stopped"`. With B accepted under the still-running T, StopFailure(T) therefore records failed, increments the idle epoch, returns send, and attaches the failure's `actionId` to B. That can also misattribute resource or failure handling to the new action. Cursor additionally changes a genuinely newer accepted turn U to failed when an older StopFailure(T) arrives, because its older-turn test exists only inside the successful-Stop branch. Probe both variants; Codex preserves working and leaves the preceding failure advisory.

4. **Codex — `src/agentLifecycle.ts:612` — P1: the queued work's real terminal event cannot resolve the handoff without another submit callback.** Queued input does not require a second prompt-submission callback when execution eventually starts; its own subsequent Stop must be able to establish completion without accepting known stale or duplicate Stops. After B is submitted with live ID T, Stop(T) is correctly ignored, but the action and observation history remain bound to T. B's eventual Stop(U), with a distinct execution ID, is classified as `olderTurn` solely because U differs from T and is also ignored. The probe remains working with no Stop receipt and returns wait/working, even though B's execution ended. An incomplete submission cannot receive the ordinary idle recovery nudge. The existing Codex test inserts a second correlated submit before its final Stop, hiding this case. Add coverage for T submit, Stop(T), then the queued execution's Stop(U) without that extra submit, while retaining duplicate-T and known-older-O protection.

5. **Cursor — `src/agentLifecycle.ts:739` — P2: pending input leaves the original older-Stop regression in place.** An older terminal callback must preserve the newer execution and turn identity even when pending input is nonzero. The preservation branch requires pending input to be zero; otherwise the next branch sets queued and retains the incoming older `turnId`. Reproduction: accepted working U with `pendingInputCount: 1`, then Stop(O). Cursor changes working/U to queued/O. Claude and Codex preserve working/U and keep the independent pending-input gate. Extend the existing older-Stop test with a nonzero pending count; checking only the zero-pending case misses this behavior.

6. **Cursor — `src/agentLifecycle.ts:313` and `src/agentLifecycle.ts:488` — P2: consecutive reread handoffs lose their expectation.** Multiple coordinator actions completed in one live session must retain reread tracking throughout the chain without inventing prompt acceptance. After prompted A completes, B is correctly marked `rereadExpected`, but B retains a null action session when its never-injected completion is validated. Ordering C requires a nonnull predecessor session and drops the expectation. C is consequently described as awaiting delivery despite the same live turn reading it. The A → B → C probe yields false for C's expectation only in Cursor; Claude and Codex retain it. Extend the reread test by ordering C before emitting any Stop.
