# Issue 169 implementation comparison

## Comparison

Reviewed the exported worktrees at these exact product pins:

- Codex: `d6fd390286105a45df6420b062b7b9e817302c5a`.
- Cursor: `86b34cf1f4c5f9fbe318dc4aaed349b6dac601f5`.
- Claude: `a92952226156e51a12144a8425c10d5be4b136fd`.

**Recommend Codex.** It preserves hook/workflow separation, revalidates receipt identity and activity-hook sequence, and carries the existing Codex composer/vim/submission safeguards through the no-sentinel path. No blocking finding was reproduced for that pin. Claude is the closer alternative, but its treatment of working status observations can authorize an unsafe send. Cursor has several independent safety and liveness regressions.

### Findings

1. **`src/agentLifecycle.ts:732–734` (Claude), P1 — newer working status must revoke readiness.** The rule is that an activity-bearing observation newer than `ready` invalidates it even when semantic deduplication leaves execution unchanged; only non-activity telemetry may be excluded. `kind: "status"` is not merely Claude's decorative telemetry: `src/agentEvent.ts:199–218` uses it for Antigravity's actual working/queue/background state. Excluding all status observations means a repeated `working` report after the file write changes neither receipt freshness nor `lastEventAt`. The older receipt then overrules a recently confirmed working state and the coordinator types into the agent. Focused reproduction: observe working status at T0, write a matching receipt at T10, repeat the identical working status at T20, and expose a prompt without turn chrome. Claude sent `-l, Enter`; Codex and Cursor sent no keys. Keep semantic deduplication, but retain the arrival of activity-bearing status observations.

2. **`src/agentLifecycle.ts:688` and `src/state.ts:1437–1443` (Cursor), P1 — hook receipt bookkeeping must not invalidate workflow authority.** Hook traffic must remain separate from cursor compare-and-swap authority so correlated acceptance can finish a send safely. Advancing the receipt through `mutateCursorsState` increments workflow state revision on every non-telemetry hook. A normal prompt-submit hook arriving after the first submit key therefore makes the next `assertAuthority` fail before the override can recognize acceptance; the charged reservation survives, and the next tick creates a `delivery-uncertain` hold. Focused reproduction: emit the matching action/digest prompt hook during Codex's `C-j`. Cursor left `reserved: true` and held the issue on the next tick; both other pins ended successfully with no fallback `C-m` and no hold. The issue occurs on expected hook traffic, not just owner controls or a malformed callback.

3. **`src/runLoop.ts:1155–1165` (Cursor), P1 — receipt authority must remain revocable through submission.** Every key using file proof must recheck the observed receipt, not only a cached lifecycle snapshot. This callback never rereads `ready` or compares its identity. Removing or replacing the file after the initial eligibility read therefore does not revoke the send. Focused reproduction: remove `ready` immediately after the literal paste. Cursor still sent `Enter` and recorded success; Codex and Claude stopped after the paste and retained the existing `delivery-uncertain` hold. Deletion before any key should instead defer without a charge. Successful cleanup must likewise refer to the observed file, rather than only its action UUID.

4. **`src/tmux.ts:336–337` and `src/tmux.ts:1111–1114` (Cursor), P1 — file proof cannot waive the empty-composer guard.** Before any key, Codex's composer must be empty or contain only its recognized placeholder. The new `codexReadyForFileProof` condition is additive: its false result falls through to unconditional readiness, and the pre-paste per-key branch checks only sentinel proof. Thus a valid receipt permits a literal paste into an existing owner draft. The later exact-message check refuses only after contaminating the draft and charging a send. Focused reproduction with `› owner draft` and no sentinel produced one literal paste and a mid-send refusal in Cursor; the other pins emitted no keys.

5. **`src/tmux.ts:242–259`, called at `src/tmux.ts:1074` and `src/tmux.ts:1097–1098` (Cursor), P2 — vim and submitted-message detection must also work without the sentinel.** File-backed delivery must preserve the complete existing key protocol, not merely find a composer for its post-paste check. These two helpers still anchor exclusively below the sentinel. With a visible `Vim: Normal` footer but no sentinel, Cursor omits `i` and sends the action text as normal-mode input. Separately, when `C-j` visibly submits the exact nudge and starts its turn before a hook arrives, Cursor cannot recognize that acceptance and returns a mid-send `codex-turn-chrome` refusal, causing an unnecessary delivery-uncertain hold. Focused key probes reproduced both outcomes. Codex and Claude sent `i` for NORMAL and recognized visual acceptance after `C-j` without sending a fallback key.

6. **`src/runLoop.ts:2002` (Cursor), P2 — accepted amendment readiness must survive order retirement.** A receipt for the last accepted amendment request must remain available until a successful next-action send; retiring an action is not delivery. `beginAmendment` records the requester's accepted UUID and immediately runs this unconditional deletion. If the agent has already written readiness, stale working state and an absent sentinel can then block the amendment ballot indefinitely. The isolated persisted-retirement probe deleted the requester's matching receipt only in Cursor; both other implementations preserved it. Retirement of unanswered peers must not confer acceptance, but that does not justify deleting the accepted requester's proof.

7. **`src/tmux.ts:1048–1054` (Cursor) and `src/tmux.ts:1032–1035` (Claude), P2 — unavailable capture must fail closed on a file-backed override.** A receipt substitutes for the sentinel, not for the ability to inspect current dialog/turn vetoes. Both implementations turn a failed capture into an empty string, which the Cursor-agent prompt predicate accepts. With a live foreground process and stale-working override, they therefore paste and submit without having observed whether a blocking dialog or turn is present. The focused empty-capture probe sent `-l, Enter` in both alternatives. Codex returned `pane-capture-unavailable` before any key. Cover initial capture and recapture before subsequent keys, preserving ambiguous-send handling if a key has already gone out.

### Scope, reuse, and coverage

All three pins stay within the same 15 approved product paths, extend existing test files, add no dependency or new product file, retain both completion modes, and keep the startup `bash` foreground veto. Their coordination artifacts are not additional product scope.

- **Codex:** reuses mailbox containment, lifecycle mutation, cursor acceptance, delivery reservations, and the existing Codex tail/composer helpers. The bounded descriptor read rejects nonregular/symlink inputs and detects identity changes. Test additions cover Git and response acceptance, amendment acceptance, restart/single-send behavior, timestamp and identity failures, duplicate hooks, shell recovery, file/hook races, and the existing per-key scenarios parameterized for both proof sources. The extra coverage is directly tied to the receipt contract rather than unrelated refactoring.
- **Claude:** similarly keeps receipt freshness in lifecycle state and factors composer parsing through a small anchor choice. Existing fixtures cover response acceptance, freshness, and several no-sentinel key cases. Its exclusion of both status and telemetry is broader than the justified telemetry exception, and the tests do not exercise a newer duplicate working status or unavailable Cursor capture. This is a focused implementation, but not safe unchanged.
- **Cursor:** reuses the delivery path and mailbox helpers, but adds a second workflow-state write for each activity observation and duplicates portions of the footer/composer helpers instead of carrying the existing safeguards through one proof-selection path. Its focused tests cover basic eligibility and happy-path receipt delivery; the existing per-key matrix remains sentinel-only. The missed interactions are observable in the findings above, not merely stylistic concerns.
