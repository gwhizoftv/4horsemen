## Findings

1. Cursor plan, `src/setupWorkspace.ts` / `src/tmux.ts` (`ensureCursorAgentVimOff` writes `editor.vimMode` into `<clone>/.cursor/cli.json`); same claim in the antigravity plan's per-clone wiring. The project file is parsed with the permissions-only strict schema (`r0`: `{ permissions }` plus `.strict()`), then merged into the full config. `editor` is not in that schema. Followed as written, Cursor agent startup fails validation with `Unrecognized key(s) in object: 'editor'`, or the key is dropped and the home `editor.vimMode` stays in force. Either way the nudge path still sees vim on. Smallest correction: do not write `editor` into `.cursor/cli.json`. Point `CURSOR_CONFIG_DIR` at a clone-local directory whose `cli-config.json` is a copy of the resolved config with only `editor.vimMode` set false. That variable is the directory of `cli-config.json` only; `CURSOR_DATA_DIR` still selects projects and other state.

2. Cursor plan, codex plan, and antigravity plan, Claude `launcher_command` adding `--settings '{"editorMode":"normal"}'`. `resolveEffective` in `src/claudeStatusLine.ts` treats any launcher `--settings` as ambiguous and does not install the status-line tee. Followed as written, every regenerated Claude launcher turns Claude quota telemetry off. Smallest correction: set `editorMode` on the clone `.claude/settings.local.json` document `plannedDocument` already writes. That layer outranks `~/.claude/settings.json`. Do not pass `--settings`.

3. Codex plan, Cursor snapshot when no `cli-config.json` exists: "use the vendor's minimal configuration with version 1 and empty allow/deny lists." The vendor default already has `editor.vimMode: false` and a non-empty `permissions.allow` (including `Shell(ls)`). Followed as written, a machine with no config file gets an empty allow list, so the agent is denied tools the vendor default would allow, in order to set a vim bit that is already false. Smallest correction: if the resolved file is absent, do not set `CURSOR_CONFIG_DIR`. Copy and override only a file that exists. Keep the plan's refusal to replace an unreadable file with empty permissions.

4. Claude plan, Cursor section and Alternatives: project `.cursor/cli.json` must not carry `editor`, and `CURSOR_CONFIG_DIR` must not be set, so the owner edits `~/.cursor/cli-config.json`. The issue requires the driver to run each agent with vim off without editing the owner's home config. The project-file ban is right (finding 1). The `CURSOR_CONFIG_DIR` ban is not: that variable changes only the `cli-config.json` directory, not `CURSOR_DATA_DIR`. Followed as written, a Cursor whose home `editor.vimMode` is true still starts in vim, `readCursorVimMode` still selects the vim prelude, and lost prompts remain. Smallest correction: the clone-local `cli-config.json` snapshot in the codex plan, with `CURSOR_DATA_DIR` left unset.

5. Claude plan, `removeAgentLifecycleHooks`: delete `editorMode` when its value is `"normal"`. Sync claims an owner's explicit value is kept. Removal today deletes only hook entries that carry the managed marker. Followed as written, uninstall removes `editorMode: "normal"` even when the owner set it before install. Smallest correction: delete `editorMode` only when this install added it.

6. Antigravity plan, `pipeToLog` perl one-liner, and the isolated-tmux test that every log line matches `^\[timestamp\]`. The `print strftime(...)` sits in `BEGIN`, so it runs once; `-p` then writes the pane lines with no prefix. The same command contains `%Y` and is given to `pipe-pane`, which expands `%` the way it expands `#`. Followed as written, tmux rewrites the perl program, the log is not per-line stamped, and the new test fails. The raw issue-199 log is also no longer the pane's own bytes. Smallest correction: keep the raw `.log` and write a sidecar, and escape both `#` and `%` in the pipe command. A missing `perl` must not replace a working `cat` pipe with a failed one.

7. Antigravity plan, `proposeProjectPolicy` documentation profile: `verify` empty when there is no `check:docs`, plus an unnamed "minimal check". `documentationProfileSchema.checks` is `min(1)` and the plan does not change `src/state.ts`. Followed as written, `buildWorkspaceConfig` rejects the profile, so install of a Node repo that has docs and no `check:docs` throws. Smallest correction: allow an empty `checks` array on the documentation profile only, and list `src/state.ts`.

8. Antigravity plan, launcher flags without a `resolveNudgeKeys` change. With Claude vim off, no `-- INSERT --` marker is shown, and an empty prelude still calls `vimInsertPrelude`, which returns `["a"]`. Followed as written, the nudge text is `a Read and execute …`. Codex `nudgePrelude: []` in new defaults does not by itself fix a config that still stores `["i"]` unless the send path requires `Vim: Normal`. Smallest correction: send Claude `a` only for a visible NORMAL or VISUAL marker, and send the default Codex `i` only for `Vim: Normal`.

9. Cursor plan, Node proposal cache on the final `check` or `test` script (`tree-excluding-evidence` and `node_modules`). `docs/setup-workspace.md` keeps `install` and `build` uncached, and `config.example.json` caches lint, typecheck, and the split test commands, not `pnpm run check`. This repo's `check` script is `pnpm build && pnpm check:fast && pnpm test:e2e`. Followed as written, a receipt for `check` skips that build on the next equivalent tree. The antigravity plan has the same gap: it attaches that cache object to finalization checks and does not say `build` stays uncached. Smallest correction: do not declare `cache` on `install`, `build`, or a script that runs them. Cache only commands whose inputs are the declared tree and `node_modules`, or leave cache to an explicit `--declare` of the example's component list.

## Conclusion

All four plans stay inside issue 213, name existing modules rather than new product files, and extend current test files. They are not interchangeable. A plan that can be implemented has to use Claude's clone `settings.local.json` for `editorMode` (not `--settings`), Codex's `-c tui.vim_mode_default=false`, and a `CURSOR_CONFIG_DIR` snapshot of `cli-config.json` for Cursor (not `.cursor/cli.json` and not the owner's home file). Preludes fire only on positive vim evidence. Terminal time is a sidecar beside the raw log, with `#` and `%` escaped. Documentation exemptions are an explicit profile, including an empty final-check list when no docs command exists. Coordinator cache is not guessed onto `pnpm run check`; `coord onboard --declare` is the route that installs the reviewed example, and re-onboard must not drop that declaration. Receipts stay in `<coord-runtime>/verification/receipts/` and are already shared by every issue and agent of that one runtime.
