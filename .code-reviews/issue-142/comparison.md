## Comparison

Reviewed the exact materialized implementations:

- Claude: `64ace635ff399b21a136cf1f8ced9c526346fa45`.
- Cursor: `da473de2bc7a3e5cc65651d28abb3704ce5f12fb`.
- Codex: `39d7179cb242b64f791dc4dc2e5aada3e9a23b4f`.

**Recommendation: use Codex as the revision base, but approve none of these pins as-is.** Codex has a reproducible Git-environment scoping defect. Claude and Cursor require substantially more correction: their 19 changed product/test files are byte-for-byte identical, and the shared findings below apply to both pins.

### Blocking findings

1. **P1 — Claude and Cursor, `src/shellGuard.ts:401-405` (assignment collection at `299-304`).** Classification must not execute candidate scripts or candidate-controlled startup code. The guard forwards every candidate assignment into the Bash policy-check process. Consequently, `BASH_ENV='/path/to/startup.sh' git status` sources that file while deciding whether to deny the tool request. In a disposable fixture, a startup file wrote a marker even though the guard returned `deny: true`; the candidate command was never submitted to a shell for execution. This is a side effect before enforcement, not merely unsupported shell syntax. Add a test asserting that a candidate-provided startup file is never executed during classification. Codex does not forward this candidate assignment and did not create the marker.

2. **P1 — Claude and Cursor, `src/agentLifecycle.ts:281-302`.** Active coverage must require affirmative actual-tool refusal evidence tied to a known current session and current policy/configuration; an emitted hook response is not proof of harness enforcement. Here, any recorded denial plus a later resolution probe becomes `hook: active` unless a separate negative `refusalRan` record exists. Missing session identities are accepted as matching. Calling the classifier with null lifecycle/denial/probe session IDs, no CLI version, a denial, and no refusal result returned `{ hook: 'active', shim: 'bypassed' }`. A direct hook-subprocess call followed by a probe can therefore claim active coverage without the harness ever honoring a denial. The classifier also compares stored revisions to each other, not to the current installed hook configuration; removing/disabling the hook does not invalidate that evidence. Test unknown identity, hook-response-only evidence, and configuration changes as unverified rather than active. Codex instead requires an explicit observed outcome, session/version, probe-specific denial, and a current configuration/shim binding.

3. **P2 — Claude and Cursor, `src/shellGuard.ts:549-553,569-577`.** A probe prescribed for execution inside the actual sandboxed tool must be able to publish its observation through the existing narrow writable roots, without granting access to coordinator-owned state. Both probe paths directly mutate `agent-lifecycle.json` and the journal. The Codex launcher grants the completion drop, responses, and materialized inputs/worktrees (`scripts/lib/launcher.sh:310-359`), not the owner runtime containing these files. Thus a normal sandboxed probe fails to record coverage, and the negative tail cannot reliably record that a supposedly refused request actually ran. This is a code/permission-boundary finding, not a claimed live smoke result. Exercise the probe with owner state read-only and only clone/mailbox roots writable. Codex uses a bounded clone-local observation mailbox and coordinator-side ingestion instead of widening the grant.

4. **P2 — Claude and Cursor, `src/shellGuard.ts:253-257,349-357`.** Static recognition must preserve parent-shell directory scope for supported literal subshells and pipelines; it must neither exempt clone reads nor refuse unrelated repositories by attributing the wrong cwd. All separators collapse to the same token, and every segment shares the mutated directory. In disposable repositories, both `(cd '<other>'); git status` and `echo ok | cd '<other>'; git status` returned allow even though the subsequent Git runs in the original clone under Bash. Reversing the subshell example can wrongly refuse an unrelated repository. Test these alongside ordinary parent-shell `cd`. Codex retained the original cwd and denied both fixture requests.

5. **P2 — Claude and Cursor, `src/agentHookSync.ts:51-53`.** The raw-payload fast path must not discard literal Git commands recognized by the decoder/parser. It only looks for the contiguous bytes `git`. A payload whose command is JSON-escaped `g\u0069t status`, or the literal shell command `g'it' status`, goes straight to allow without invoking the decoder. Running each generated hook against these payloads confirmed the decoder was skipped, while an ordinary `git status` payload reached it. This defeats the native guard when PATH bypasses the shim. Add rendered-hook tests for JSON escapes and quote concatenation. Codex routes both examples to its decoder.

6. **P2 — Claude and Cursor, `src/agentHookSync.ts:193-219,286-289`.** Synchronization and removal must preserve owner handlers, including ones sharing a managed Antigravity set or matcher group. Synchronization replaces the entire `coord-agent-lifecycle` set; removal deletes it wholesale once any managed marker is present. Adding an owner command beside the generated `PreToolUse` handler, then synchronizing, lost that command. Adding it again before removal also lost it. Both results were reproduced for each pin. Test owner siblings through sync and uninstall, not just unrelated top-level sets. Codex preserved them in both operations.

7. **P2 — Codex, `src/shellGuard.ts:147-156`.** Git targeting supplied to the policy check must reflect the environment actually exported to the subsequent external Git process. An assignment-only shell segment does not export a previously unexported variable. Nevertheless, `GIT_WORK_TREE='<other>'; git status` persists that assignment into the guard's environment for the later Git call. With no inherited exported `GIT_WORK_TREE`, the guard returned allow in a fixture, while Bash's `unset GIT_WORK_TREE; GIT_WORK_TREE='<other>'; /usr/bin/git rev-parse --show-toplevel` still identified the original clone. The actual status operation would therefore be a forbidden clone read if PATH bypasses the shim. Add focused tests distinguishing assignment-only shell locals, inherited exported variables, and leading assignments directly on the Git command. Claude/Cursor denied this particular fixture request.

### Scope, reuse, and focused coverage

All candidates stay within the issue's product file map, retain the PATH shim, and reuse its policy via check mode rather than implementing a second Git permission policy. They extend the existing hook installer/remover, lifecycle persistence, `agent-lifecycle` journal event, CLI, doctor/report, and action/protocol plumbing. None introduces a dependency or changes the deferred `hookPolicy.ts` environment boundary or `state.ts` schema.

The new `src/shellGuard.ts` and focused `test/shellGuard.test.ts` are justified by the shared vendor adapters, bounded recognition, and cross-policy tests. Other coverage extends existing test files; no unrelated product refactor or extra tracked abstraction is needed. Claude/Cursor's identical implementation is not an independent alternative with different tradeoffs. Their tests cover useful vendor response, manual-mode, missing-shim, pinned-read fallback, and lifecycle cases, but their coverage test treats a hook callback plus probe as success and misses the above process/sandbox boundaries.

Codex offers the better corrective-work base: explicit parsing/check budgets, subshell/pipeline scope, safer candidate environment handling, conservative coverage invalidation, preservation of owner handlers, and the observation mailbox needed by the existing sandbox grants. These are issue requirements rather than speculative flexibility. Its environment-state tracking still needs finding 7 corrected; passing focused parser tests did not establish faithful shell export semantics.

### Validation and limits

The review executed the exported functions from all three bound worktrees using in-memory TypeScript transpilation. Disposable repositories and startup-marker fixtures lived under a bound worktree's `.codex/tmp/`; no candidate Git status/diff command ran against this working clone. It also executed generated prefilter commands and AGY sync/removal against fixtures, and compared the 19 listed product/test files directly to establish Claude/Cursor equivalence. Findings 1, 4-7 have the concrete reproductions described above; finding 2 includes a direct classifier reproduction; finding 3 follows from the launcher grants and writes.

The Codex product pin previously passed `pnpm check` (709 fast tests and 2 e2e tests). Before publishing this comparison, `pnpm check:fast` passed again: lint, typecheck, and all 709 tests in 41 files. These automated results and the review reproductions are **not** four-vendor live-harness acceptance. I did not perform actual shell-tool resolution/refusal smoke in freshly loaded Claude, Codex, Cursor, and Antigravity sessions, and the inspected bound artifacts do not supply equivalent evidence. Before claiming containment, validate each installed version through its actual tool, record session/version/policy/config binding and observed outcome, and repeat after restart or relevant configuration changes—not on every coordinator action. Unknown or inactive integrations must remain visible rather than counted as success.
