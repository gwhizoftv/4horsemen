## Findings

1. **Cursor — Exact File List / runLoop guidance consume:** The plan says `prepareAction`/`buildOrder` should “copy queued guidance into the order and clear it from `cursors.json`.” Rule: every agent ordered for the same workflow step must receive identical advisory guidance for that step (issue: turn-boundary delivery into the next prepared `action.md` cohort). Failure if followed as written: the first agent’s prepare clears the queue, so later peers (or a reissue/rewrite after a concurrent `/steer`) get empty or newer text and diverge mid-cohort. Smallest correction: bind a durable per-step snapshot once (as Claude’s `bindOwnerGuidance` / Codex’s active snapshot), have `buildOrder` read only that snapshot, and keep later `/steer` text pending until the next step.

2. **Cursor — Exact File List / `InternalOrder` shape:** Claims `ownerGuidance?: string` while state work is a queued list and Tests expect multiple steer entries. Rule: the order field must be able to carry every bound entry without silent truncation. Failure: implementers pick a single string, drop all but one steer, and tests that expect multiple bullets cannot pass. Smallest correction: use `ownerGuidance?: readonly string[]` (Claude) or an equivalent list.

3. **Cursor — Exact File List / `src/tmux.ts`:** Listed as “no behavior change expected … touch only if a tiny export is required.” Rule: the changed-file list must name every path the implementation may edit, with no optional maybe-touch entries. Failure: scope/file-map checks cannot tell whether a `tmux.ts` edit is in or out of plan. Smallest correction: omit `tmux.ts` unless a concrete missing export is already identified; attach already goes through existing `cli`/`TmuxController` APIs.

4. **Claude — Reuse and Scope / `rederiveAfterDrop`:** Lists `rederiveAfterDrop` among existing facilities as if it were a reusable `state.ts` export alongside `setPaused`/`dropAgent`. Rule: reuse claims must name symbols that actually exist at the cited layer. Failure: an implementer searches `state.ts`, does not find it (it is a private helper in `cli.ts` today), and reimplements drop rederivation incorrectly. Smallest correction: state that `rederiveAfterDrop` is extracted from private `cli.ts` into `ownerControls.ts` (which the Created-files section already implies).

5. **Codex — Durable guidance / boundary wiring:** Requires promoting pending→active at `advance`, `amendmentTransition`, owner-answer retry/revise, and `rederiveAfterDrop` whole-cohort resets, with a generation counter to distinguish same-step new cohorts. Rule: the issue’s turn boundary is the preparation of the next step’s `action.md`, and the file map must stay the smallest change that fully solves it. Failure if followed as written: miss one of the scattered transition sites and guidance stays pending forever or attaches on the wrong cohort; the plan’s own Risks section admits this class of bug. Smallest correction: bind lazily on the first `prepare-action` for a new `(stepId, round)` key (Claude), and treat same-step owner retry as a new bind key the same way the machine already advances rounds—or explicitly key bind by a cohort id the machine already writes—without five separate promotion call sites.

6. **Codex — Exact File List / `coord steer` + `issueReport.ts`:** Adds an external `coord steer` command and expands `issueReport.ts` for question/guidance status. Rule: stay within the issue’s proposed surfaces (TTY hotkeys, inline owner-question prompt, queued `/steer` into `## Owner guidance`) and justify every extra surface. Failure: implementation grows CLI surface and report formatting beyond what is required to unlock the three features, delaying the smallest complete fix. Smallest correction: keep enqueue helper internal for the interactive `/steer` path (external `coord steer` optional later); status hotkey `s` can keep calling today’s `renderIssueReport` unless a missing field is shown to block the issue.

**Scope / reuse / tests (cross-plan):** All three stay on the issue’s three features, reuse `mutateCursorsState` / journal / pause / drop / answer / `buildOrder` / advisory action sections, justify a new TTY adapter, and prefer extending existing test files. Claude’s plan is the strongest on multi-agent guidance consistency, AbortSignal wake for `q`, prompt-safe logging, and TTY injection via `CliDependencies`. Cursor is thinnest but unsafe on guidance consume. Codex is thorough on terminal safety and stale ID revalidation but over-scatters boundary promotion and widens CLI/report scope. Prefer Claude’s bind-once-at-prepare model, Cursor/Claude’s `ownerControls.ts` extraction (needed because interactive must not call CLI handlers that `runTick()`), and Codex’s stale-question / raw-mode teardown disciplines without adopting its multi-site promotion or `coord steer`/`issueReport` expansions.

## Conclusion

Do not implement Cursor’s clear-on-prepare guidance as written (cohort divergence) or Codex’s multi-site promotion/`coord steer` expansions as the default. Accept Claude’s plan shape—TTY session + shared ownerControls without a second tick, bind-once guidance snapshot at first prepare-action for the step, advisory `## Owner guidance`, AbortSignal quit—after fixing the `rederiveAfterDrop` reuse citation, and fold in Cursor’s omission of speculative `tmux.ts` edits plus Codex’s stale-ID and raw-mode teardown requirements.
