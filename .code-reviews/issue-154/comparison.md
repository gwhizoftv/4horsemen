## Comparison

Protocol version: 1. Reviewed the coordinator-exported worktrees at these exact product pins:

- Claude: `6940cdb27af69c2e2332f3d605f83625fd790634`.
- Cursor: `181ea79ca43a7f799e9635dbc5435ea50eaddb2b`.
- Codex: `6990dfbc8b26b78375dfc2e1b879b51c2f9d46e1`.

**Recommendation: select Codex.** Claude is the next-best base, but has the two shared recovery/shutdown findings below. Cursor has additional reproducible destructive-input and foreground-exit failures. I found no blocking defect in the Codex pin during this comparison; that is a review result, not a claim that every platform path was exercised.

### Implementation findings

1. **[P1] Cursor — `src/interactive.ts:264–265`, `219–232`, `326–328`.** The rule is that pasted terminal data must not become a sequence of destructive owner controls. `emitKeypressEvents` splits a single input chunk into individual keypress events, so the multi-character `key.sequence` check runs too late. Writing the single raw chunk `d2` to the supplied input dropped `codex` in the probe, without a deliberate menu interaction or confirmation. The same path can select an abandon answer. Add a regression using `input.write("d2")`, not synthetic `keypress` events, and assert no mutation; also cover bracketed paste.

2. **[P1] Cursor — `src/interactive.ts:84–93`.** Quitting must relinquish the coordinator's stdin ownership so the foreground process can actually exit, while leaving agent sessions alone. Cleanup removes the custom keypress listener but neither pauses stdin nor removes the data reader installed by `emitKeypressEvents`. After `q`, the probe showed `aborted=true`, `raw=false`, `readableFlowing=true`, and one remaining data listener. A real PTY process stayed alive three seconds after quit and exited only when the probe watchdog paused stdin. Add a child-process/PTY exit assertion, not only an assertion that the abort flag changed.

3. **[P2] Cursor — `src/state.ts:1282–1285`; `src/ownerControls.ts:312–347`.** A whole-cohort owner retry must be a fresh guidance boundary even when the ballot's step and round repeat. The retry clears the ballot actions/responses but retains the old guidance key; the next bind returns unchanged. Guidance queued while the owner resolves a split therefore misses the retried ballot and can remain pending through repeated retries. A helper-level probe bound `R6.ballot/1`, queued advice, applied the implementation's retry identity behavior, and rebound the same round: Cursor delivered nothing and retained the advice in pending; Claude and Codex delivered it. Extend the owner-answer regression to queue advice before `retry` and assert that the new ballot cohort receives it.

4. **[P2] Cursor — `src/interactive.ts:68`.** Interactive activation must preserve log-only behavior when output is redirected, not merely when stdin is non-TTY. With TTY input and non-TTY output the session still enables raw mode and writes prompts/ANSI controls into the output stream. The direct stream probe returned an active session with `raw=true` for this combination. Add the input-TTY/output-non-TTY case and require a null session with untouched streams, as the other implementations do.

5. **[P2] Cursor — `src/runLoop.ts:2940–2949`, with the default timer at `870`.** A poll that finishes normally must release its abort listener, and abort must cancel the owned timeout rather than merely stop awaiting it. This race leaves a listener after every normal sleep and leaves the default timeout running after quit. The isolated run-method probe counted eleven retained abort listeners after eleven completed sleeps; a configured 60-second poll can also retain its timer after the runner returns. Test both repeated polling with a stable listener count and default-timer cancellation, rather than only racing a never-resolving injected promise.

6. **[P2] Cursor — `src/cli.ts:707–710`.** A manual-pause toggle must derive its next value inside the same locked mutation that applies it. Here the callback reads `manualPaused` before entering `setManualPause`'s lock. If another owner process changes that flag between the read and mutation, the key writes an obsolete inversion instead of toggling the current state; for example, an intervening pause can leave the issue paused when the key is applied. Inject that intervening update in a regression and assert inversion of the locked state. Claude and Codex pass a toggle operation into the locked helper instead.

7. **[P2] Claude — `src/runLoop.ts:2935–2939`; Cursor — `src/runLoop.ts:2921–2925`.** Once foreground stop has been requested, finishing an already-running initialization effect must not authorize a new workflow tick. Both methods await initialization and then unconditionally call `runTick`, even if `q` or Ctrl-C aborted the signal during the await. That new tick can prepare/deliver actions or begin publication after the stop request. Fault-injection probes of the exact run-method bodies aborted inside `initializeEffects`: Claude and Cursor each started one subsequent tick; Codex started zero. Keep a regression asserting zero tick calls after initialization resolves with an already-aborted signal.

8. **[P2] Claude — `src/state.ts:1304–1310`; Cursor — `src/state.ts:1282–1294`.** Backward-compatible guidance defaults must not let an already-started cohort acquire new advice for only its remaining recipients. In an older runtime with no guidance field, one agent can already have an action while another is still idle after interrupted preparation. Queuing advice and resuming binds that advice to the remaining action in both implementations, although the first agent is already working without it. Helper-level probes reproduced delivery into that partially prepared cohort and an emptied pending queue. Codex freezes an empty legacy snapshot and retains the queued advice for the next boundary. Add an upgrade fixture with one existing action and one unprepared peer, then assert equal current-cohort guidance and retained pending text.

### Scope, reuse, and coverage

All three implementations stay within the approved product file map: the same fourteen source/test/documentation paths, with only `src/interactive.ts`, `src/ownerControls.ts`, and `test/interactive.test.ts` newly introduced. None changes dependencies, hooks, the shared report renderer, or tmux pane-input handling. All reuse the existing locked state helpers and extract the existing answer/drop logic rather than starting another tick loop from hotkeys. Each supplies step/roster information in the CLI status callback and renders advisory guidance in both submission modes.

- **Claude:** cohesive owner-control extraction, atomic pause toggle, same-round batch identity, both-stream TTY gating, cancellable default sleep, destructive-action confirmation, and quit/completion protection. Its focused tests drive raw data chunks and include signal cleanup, stale questions, guidance reissue/restart, and timer cancellation. The missing interrupted-initialization and legacy-partial-cohort cases are substantive gaps, not reasons for a larger refactor.
- **Cursor:** similar scope and reuse, but its terminal tests synthesize `keypress` events and therefore bypass the very data-to-keypress conversion that defeats paste protection. Tests check the abort flag rather than foreground process exit, and guidance tests only distinguish different step/round keys. The implementation also computes the pause inversion outside the shared mutation. These are gaps in the three requested features, not unrelated cleanup requests.
- **Codex:** adds focused raw-stream/paste, cleanup, completion-race, between-recipient CAS, legacy-cohort, same-round identity, amendment-restoration, and default/injected-sleep tests while extending the existing test files. The generation and suspended-guidance snapshot add durable state beyond the plan's initial sketch, but remain confined to guidance recovery and are documented/tested; there is no new generic framework or dependency. The custom terminal parser is extra implementation complexity relative to using readline, balanced here by explicit paste, UTF-8, and one-line redraw handling.

### Validation and limits

Read the exported implementation sources and their focused tests directly; no peer fetch, pinned `git show`, or re-derived Git diff was used. Read-only, in-memory TypeScript probes exercised the exported terminal modules and state helpers; state probes resolved unchanged supporting modules from the tested local build. Separate fault-injection probes executed each exact `run` method with controlled initialization/sleep dependencies. The Cursor exit failure was additionally reproduced in a real PTY with a cleanup watchdog.

The fourteen local Codex product files were byte-compared with the exported Codex pin and matched. That product passed `pnpm check`: 733 fast tests and two end-to-end tests, plus the earlier PTY controls/redraw/quit smoke. The comparison publication also runs the required `pnpm check:fast`. I did not run the peer full suites or manually exercise native macOS Terminal attachment/direct agent-pane typing; no such verification is claimed.
