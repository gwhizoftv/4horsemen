## Findings

1. **cursor — Conclusion / `src/runLoop.ts` omission.** The plan keeps today's `run()` finish rule (`paused && !resourceWorkPending`) and only eases post-exit recovery (`--hold latest` plus resume→`run()`). **Rule:** the issue requires the coordinator not to exit while continuation is still possible; a hold with observation-only ticks is still continuable after an owner release in another shell. **Failure:** following the cursor plan, every ordinary owner hold still ends the foreground `coord N` process, so the transcript's first failure mode ("coordinator exits when errors are detected") remains. **Correction:** treat automatic holds (and preferably also manual pause, or at least holds) as wait states inside `run()`, matching claude/codex, and keep a short release command for the owner.

2. **claude — Exact File List / `src/cli.ts` plain `resume`.** The plan makes bare `coord resume --issue N` release every non-`nudge-loop` hold via folded `releaseHold`. **Rule:** issue #126 and current `docs/coord-driver.md` / CLI behavior require plain resume to clear only `manualPaused`; each safety hold needs an explicit scoped acknowledgment after inspection. **Failure:** one plain resume would clear multiple independent holds (`harness-gone` plus `delivery-uncertain`, or two agents) without naming which condition was inspected, and it silently revises the audited #126 contract the existing "resumes only the selected hold…" / manual-pause wording encode. **Correction:** keep plain resume as manual-pause-only; shorten recovery with an unambiguous selector (`--hold latest` when exactly one hold, or codex's `--agent` when exactly one hold for that agent) plus optional continue/keep-alive.

3. **codex — Reuse and Scope / `snapshotCloneReadiness()`.** The plan says to reuse `snapshotCloneReadiness()` for the prepare dirty preflight. **Rule:** reuse claims must name helpers that are actually on the path being changed, or list the extraction; `snapshotCloneReadiness` is a private helper used only by `makeAgentClonesBaseReady` today, not by `prepareAgentIssueBranches`. **Failure:** an implementer may export or bend completion-readiness snapshots into start/resume prepare and inherit unrelated refuse/discard framing, or block on a "reuse" that is really a new shared API the file list never names. **Correction:** either add an explicit bullet to export/share a tiny HEAD+dirt snapshot for both callers, or describe the filter inline in `prepareAgentIssueBranches` (HEAD ≠ `issueBranchFor(...)` ⇒ blocking dirt) as cursor/claude do.

4. **cursor — Exact File List / resume auto-`run()`.** After any resume that leaves `paused === false`, the plan always calls `makeRunLoop(paths).run()`. **Rule:** resume must remain safe beside an already-live coordinator; starting a second run loop is only for a stopped process (codex states this; `assertNoManualSession` does not detect a concurrent automated `coord N`). **Failure:** if keep-alive lands (or a runner is still up for another reason), a habit of `coord resume …` would start a second `run()` and race `initializeEffects` / ticks under the same cursors lock/revision model. **Correction:** default resume stays state-only; add an explicit continue flag (codex `--run`) or only auto-continue when no keep-alive design is chosen and docs say the process had exited.

5. **claude — Tests / scope relative to #126 docs.** The plan updates recovery docs to say plain resume releases non-nudge holds, and expects the existing selected-hold CLI test to "still pass unchanged" because its only hold is `nudge-loop`. **Rule:** focused tests must fail closed on the new contract, including regressions of the old plain-resume meaning. **Failure:** without an explicit case that plain resume does *not* release a non-nudge hold (if that old rule is kept) — or, if claude's rule is accepted, without rewriting every doc/test that still teaches scoped-only release — implementers can ship the new CLI behavior while leaving contradictory README/driver text and review expectations. **Correction:** either reject the plain-resume bulk release (finding 2) or list every doc/test that asserts the old meaning as required edits, including a dedicated multi-hold plain-resume case.

Shared strength (not a defect): all three plans correctly exempt dirty clones already on the target `issue-N/<agent>` branch from the prepare preflight while still refusing dirty off-branch checkouts, and none invent new modules for that core fix. Codex best matches the issue's "do not exit" requirement while preserving scoped hold authorization; its test matrix is broader than the minimum but still extends existing files.

## Conclusion

Do not implement cursor as written: it fixes dirty rejoin and shortens UUID typing but leaves hold-driven process exit in place. Do not implement claude's plain-resume bulk hold release: it conflicts with the #126 scoped-acknowledgment rule even though its keep-alive and dirty-exempt pieces are sound. Prefer codex's combination — wait-don't-exit on holds, same-branch dirty preserve, and explicit agent-scoped release with optional `--run` — after correcting the `snapshotCloneReadiness` reuse claim to an inline or explicitly shared preflight. Whatever lands must keep `nudge-loop` + `--reset-nudge-budget`, leave completion/wipe dirty policy unchanged, and prove dirty-on-branch rejoin plus runner liveness with focused extensions of the existing prepare/runLoop/CLI tests under `pnpm check:fast`.
